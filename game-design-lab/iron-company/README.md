# 灰旗佣兵团 · 黑水渡口

参考《战场兄弟》的独立网页战术样片。一份护送合同，四名佣兵，一张有三条过河路线的地图。战前装备、站位、AP、疲劳、射界、包围和士气共同影响战局，伤亡与开销进入最后结算。

[直接打开离线游戏](offline.html) · [双击启动](open-game.cmd) · [返回五款作品的研究](../research.html?game=brothers&view=study#games) · [美术素材与提示词](assets/ASSETS.md)

## 怎么玩

1. 在整备页选择出发路线和四人的武器、护甲。所有采购共用 300 克朗军费。重甲增加保护，也降低先攻和可用疲劳。
2. 出发后依照顶部先攻顺序行动。当前队员在下方显示剩余 AP 与技能。悬停地面查看路径与代价，点击移动；选择攻击技能后，悬停敌人查看命中构成，再点击出手。
3. 保护商车到达东岸，或者击溃所有拦路劫匪。每回合结束，商车最多前进两格，需要两格内有护卫、身边没有敌人、前路没有被占据。
4. 击倒匪首可动摇其他敌人的士气，并阻止第四回合的增援。低士气者战力下降，溃逃者会寻找退路；队长的鼓舞可以帮助自己人稳住阵脚。
5. 胜利、失败或撤离后查看账册和伤亡。合同报酬 450、匪首赏金 90、全员生还奖励 60；整备采购、工资、修理准备金和每名阵亡者 80 克朗的抚恤均计入净收益。

快捷键：1–5 选择技能，E 结束当前行动，W 等待，F 网格，Esc 取消技能或关闭面板。鼠标拖动平移，滚轮或地图按钮缩放。手机可以缩放、拖动地图，并展开右下角“战况 / 目标”。

## 有哪些真正不同的选择

| 决定 | 得到什么 | 要付出的代价 |
| --- | --- | --- |
| 短矛与盾 / 双手长枪 | 矛墙和盾墙 / 两格攻击距离 | 失去另一套技能，长枪每次攻击消耗更多 AP |
| 猎弓 / 弩 | 一回合可多次快射或瞄准 / 更强穿甲 | 弩射击后必须装填；近战缠斗会封住远程射击 |
| 战斧 / 战锤 | 高伤害、劈盾与横扫 / 更强破甲 | 疲劳和 AP 不同；横扫会打到身边的队友 |
| 轻装 / 重甲 | 更早行动和更多疲劳余量 / 更厚身体与头部护甲 | 防护、先攻、持续作战和军费互相牵制 |
| 守木桥 / 绕石桥 / 走浅滩 | 保护商车 / 接近制高点与后排 / 从南侧包抄 | 不能同时保护所有方向，浅滩移动更慢 |
| 集中攻击 / 打击士气 | 尽快排除威胁 / 促成连锁溃逃 | 路线、站位、命中风险和目标优先级不同 |

鼠标悬停目标时，侧栏列出基础命中、武器、盾牌、盾墙、高低差、遮挡、距离、包围、士气、伤势和疲劳修正。掷点与实际结果记录在战报中。

## 参考依据与原创范围

- [官方战术战斗介绍](https://battlebrothersgame.com/tactical-combat/)：AP、装备、疲劳、护甲、地形、射界与永久伤亡相互作用，是本样片的规则基础。
- [开发日志：包围与盾牌反馈](https://battlebrothersgame.com/dev-blog-81-progress-update-improvements/)：额外相邻队友形成包围优势；被盾挡住和被闪避分别表现。
- [开发日志：士气](https://battlebrothersgame.com/dev-blog-20-bravery-morale/)：稳定、振奋、动摇、崩溃与溃逃；重伤、队友或首领阵亡触发检定，鼓舞帮助恢复。
- [开发日志：伤势](https://battlebrothersgame.com/dev-blog-79-progress-update-injury-mechanics/)：伤势会改变角色能力，承担风险的代价超出生命条本身。

地图、佣兵身份、商车、护送条件、三种出发阵形、增援时机、生还奖励和抚恤条款是本任务的原创设计。伤害、穿甲、命中、视线、矛墙、士气与伤势公式均为明确的缩小实现，不能当作原作数值说明。

当前是一场可以结束并重玩的合同。没有实现完整世界地图、城镇、招募、长期升级、装备掉落、战役事件和完整敌人种类；重新整备会开启一份新的合同。角色使用绘制的半身棋子，结合位移、迎击、箭矢、格挡、受击、伤亡和声音反馈。

## 保存与离线

进度自动保存到本浏览器的 `grey-banner-blackwater-v1`。导出的 JSON 包含装备、地形、队员、当前先攻和结算。完成合同的简要记录保存在独立历史键，最多十二条。旧实验室的 v2 / v3 存档不覆盖。

`offline.html` 内嵌四份美术图集、样式和全部运行代码，约 15 MiB。整个游戏无需服务器或网络资源。浏览器、打开路径或来源改变时，本地存储空间可能不同。导出文件可留作备份，目前没有界面化导入。

## 开发与验证

不需要安装 JavaScript 依赖，使用 Node.js 22：

```powershell
cd F:\codex_project1\20261104_codex_project\game-design-lab\iron-company
npm run dev
```

开发预览为 `http://127.0.0.1:5215/`。完整构建从上一级执行，会同时生成研究页、主离线入口和静态发布副本：

```powershell
cd F:\codex_project1\20261104_codex_project\game-design-lab
npm run build
npm test
npm run test:browser
npm run test:offline
```

浏览器检查需要 Python Playwright 与 Chromium。检查会通过实际页面按钮和 Canvas 点击完成整备、移动、攻击、敌方行动和合同结算，另核对保存恢复、导出、手机缩放与平移后的格子命中。战术建议器只提供合法操作建议，不在页面内直接推进或改写游戏状态。

规则和流程检查用于查错。不同种子、打法与装备仍需要持续试玩，不能据此认定游戏已经好玩或平衡。

## 文件

- `model.js`：整备、六角格、战斗、先攻、AI、士气、护送和账册。
- `render.js`：绘制地图、地形、棋子、道具、状态和动作。
- `app.js` / `style.css`：整备、操作、目标预览、战报、结算和保存。
- `icons.js`：原生 SVG 技能图标。
- `assets/`：四张 imagegen 图集与完整生成记录。
- `tests/`：规则、完整浏览器流程和独立文件检查。
