记录日期：2026 年 11 月 21 日（Asia/Shanghai）。本文数字为该日的验证快照；本地研究台“项目总结”每次进入时重新读取当前统计。后台采集统一使用 8766；研究总库保留一个指向公开研究与案例快照的链接。

一图回顾：[高清 PNG](research-map/research-overview.png) · [可编辑 SVG](research-map/research-overview.svg)。全景图汇总研究内容、网页与数据入口、处理流程、报告、验证结果、价值与边界，以及待设计和待验证的扩展方向。

## 项目目标与研究起点

做一个免费公开数据驱动的产品研究库：自动发现产品、寻找并核对官网、采集免费资料、整理带来源的中文报告，再展示到网页中。

研究起点是用户提供的 [Bizpeel 相关原帖](https://x.com/yihui_indie/status/2119973315745812674)及对其流程的拆解：用固定报告结构，把公开收入与获客动作按时间组织起来，再提供搜索、阅读和 Agent 使用入口。原帖里未展示的实现推测，不能视为我们已经核实的事实。

本轮选择先验证免费公开资料可以支撑到什么程度，重点实现发现、采集、整理、展示的完整流程。

## 我们研究了哪些内容

1. **报告结构与证据组织**：确定固定章节、来源引用、公开动作和时间线的表达方式。
2. **免费来源与覆盖边界**：区分官网、仓库、产品目录、社区记录能提供的资料，以及收入和真实流量等缺口。
3. **商业产品发现**：从仅研究 GitHub 产品，扩展到 BetaList、Show HN 和 Product Hunt，覆盖没有公开仓库的产品。
4. **官网自动核对**：解决目录地址不能当官网、同名产品误关联、开发者站点内产品路径丢失等问题。
5. **中文展示与可回查性**：保留原文、翻译缓存、匹配依据、采集失败记录和历史报告版本。

## 数据入口

| 入口 | 发现范围 | 当前取得的公开资料 | 方式与限制 |
| --- | --- | --- | --- |
| GitHub | 开源软件、自托管工具 | 简介、官网、仓库指标、README、最近四条发布记录 | 官方公开 API；受匿名请求配额限制，Stars 只作初筛 |
| BetaList | 新上线商业产品 | 产品介绍、官网链接、目录收录日期 | 公开 Atom 订阅及 Visit 跳转，每轮最多解析六条 |
| Show HN | 社区展示的新产品 | 产品链接、公开介绍、帖子日期 | HN Search 公开 API；社区提交不证明提交者代表产品方 |
| Product Hunt | 新发布产品，包括非开源产品 | 名称、简介、发布日期、原始记录 | 官方公开 RSS；产品页和跳转在本机仍可能触发 403 |
| 手动输入 | 自己指定的产品 | 官网或公开仓库对应的资料 | 网页“新建研究”提交 |

免费入口包括 [GitHub API](https://api.github.com/)、[BetaList 订阅](https://feeds.feedburner.com/BetaList)、[HN Search](https://hn.algolia.com/api) 和 [Product Hunt 订阅](https://www.producthunt.com/feed)。本轮没有使用付费数据接口。

官网匹配的辅助入口包括 Hunted.Space 同一产品记录、Apple 官方应用搜索和 Hacker News 社区链接。Apple 当前检索美国 App Store，覆盖受地区限制。候选要核对名称、功能以及同一 Product Hunt / App Store 产品的回链；搜索命中本身不足以确认官网。多个候选冲突时保留简报。

## 实现逻辑与交互

自动发现产品 → 保存候选及来源 → 去重 → 查找并核对官网 → 采集可访问的官网资料 → 整理事实和动作 → 中文展示 → 发布报告。

- 官网通常最多采集首页、一个定价页、一个内容页和一个文档页；有公开仓库时补充仓库、README 和发布记录。
- Product Hunt 官网未确认时发布中文简报；确认后继续补采并发布新版本，原简报保留。
- 官网直接展示的价格片段也可以进入报告，并引用该官网页面。
- 自动发现开启时处理已有 Product Hunt 简报；官网未确认的产品每 24 小时重试，冷却记录保存在数据库中。
- 默认每 24 小时发现一批、每批处理 5 个产品；本地服务需要保持运行。

用户入口为本地研究台 http://127.0.0.1:8766/ ：

| 页面 | 用途 |
| --- | --- |
| 项目总结 | 回顾目标、数据入口、效果、价值与限制，查看当前统计 |
| 案例库 | 搜索和浏览中文报告 |
| 采集任务 | 查看后台进度、失败原因和完成结果 |
| 自动发现 | 选择来源，管理批次、频率和发现记录 |
| 数据与方法 | 理解资料范围和报告口径 |

报告提供产品概览、生意与定价、获客入口、公开动作拆解、社媒与社区、事件时间线、竞品研究线索、来源与数据缺口八个章节。支持来源回查、原文查看、版本选择和 JSON 导出。

## 价值

- **减少重复查找和整理**：将官网、目录、社区与仓库信息放入统一结构，便于理解产品定位、定价和公开做法。
- **支持案例比较**：用相同章节寻找内容、试用、文档、社区和开发者生态中值得研究的做法。
- **积累可回查的资料**：保留来源、匹配记录和历史版本，支持以后核对与更新。
- **沉淀可复用流程**：发现、核对、采集、报告与展示可以逐段改进，为后续分析或 Agent 使用提供基础。

当前适合回答“这个产品做什么、公开做过哪些事、哪些做法值得继续研究”。实际节省多少时间、是否帮助做出更好的产品决策、是否有人愿意付费，尚未通过用户对照或商业验证。

## 对我们的意义

把零散收藏推进成可回查、可比较的案例，为产品选题、竞品学习、理解公开做法和提出小实验假设提供依据。采集、身份核对、报告与版本保存的方法也能复用到后续研究。

这项实践同时帮助我们理解信息产品的维护成本和证据边界：先核对来源能支持什么，再判断需要补哪些数据、是否值得继续投入。决策改善、实际省时、使用频率和商业价值仍需真实使用验证。

## 公开阅读与本地采集

公开研究页沿用 GitHub Pages，提供同一套前端的只读快照，可阅读总结、原引导图、案例、历史版本与来源摘录；页面标明快照时间。新增采集、自动发现设置和报告更新在本地 8766 执行。完整 SQLite、采集正文、模型、配置和凭据保留在本机。

## 当前限制

1. 未接入 Stripe 等授权收入数据，没有连续收入序列、已核验 MRR、真实访问量、搜索排名和渠道转化。
2. 公开动作与时间对齐只能形成研究线索，不能证明收入变化的因果关系；当前也未实现收入归因折线图。
3. Product Hunt 的 403 本身没有解除；免登录方案受公开目录、社区索引、App Store 地区和回链覆盖限制。
4. robots.txt、接口限额、网络、证书、动态渲染和单页 2 MB 上限都会影响采集；缺项需要结合报告提示判断。
5. 规则提取和本地翻译可能遗漏上下文或误译术语。中文展示不是强模型完成的深度商业分析，保留原文供核对。
6. 获客入口只表明公开存在，社媒账号链接不等于已采集完整帖子、互动或已确认账号归属。
7. 竞品章节当前提供研究线索，尚无独立验证过的完整竞品拆解表。
8. 数据存储和 Worker 均在本机，停止服务会暂停任务。MCP、用户画像、个性化实验和多用户部署属于后续范围。

## 继续开发时从哪里接手

当前技术结构：原生 HTML / CSS / JavaScript → FastAPI → SQLite；后台 Worker 执行发现、采集、报告生成和本地翻译。

| 位置（相对子项目） | 作用 |
| --- | --- |
| `casebook/public_products.py` | 产品目录、订阅和社区来源适配 |
| `casebook/discovery.py`、`discovery_store.py` | 发现、去重、候选、来源状态和计划任务 |
| `casebook/website_resolver.py` | 官网候选查找、名称/功能/回链核对 |
| `casebook/network.py`、`collect.py` | 公网校验、robots.txt、页面及仓库采集 |
| `casebook/report.py`、`models.py` | 固定报告结构、引用、覆盖范围和数据缺口 |
| `casebook/localize.py`、`reviewed_zh.json` | 本地翻译、校验和人工核对译文 |
| `casebook/worker.py`、`db.py` | 后台任务、租约、原子发布和版本保存 |
| `static/` | 网页与本回顾文档 |
| `report.schema.json` | 报告 JSON schema |
| `data/casebook.sqlite3` | 正式项目、任务、来源、翻译、报告和设置；需要保留 |
| `tests/` | 隔离样本中的流程、错误、去重与官网核对验证 |

后续扩展前先明确：要补哪类用户问题、哪些证据能支持结论、如何验证同名产品不会误关联，以及如何保留旧报告与失败记录。增加数据来源时沿用已有来源适配与引用结构；新增指标时写清采集时间和口径。涉及正式数据库的修改应先保留可恢复副本。

启动：`python run.py --open`。检查：`python -m pytest -q` 与 `node --check static/app.js`。完整运行与依赖说明见子项目 `README.md`。
