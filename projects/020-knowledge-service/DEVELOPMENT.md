# Flowdesk · 客服架构实验室

一个独立的本地子项目，用网页梳理并运行 AI 客服的核心流程：会话状态、流程路由、知识检索、业务工具、用户确认与人工交接。

## 运行

需要 Node.js 22 或以上，无第三方依赖，无需安装。

```powershell
cd F:\codex_project1\20261104_codex_project\support-flow-lab
npm start
```

打开 http://127.0.0.1:5216/ 。开发时可运行 `npm run dev` 启用 Node 的文件监听重启；前端修改后刷新网页。没有构建步骤。

```powershell
npm run check
npm test
```

## 网页内容

- **架构总览**：接入双模型机制图、知识库价值图，支持切换、放大与原图查看；保留可点击的节点与职责边界、单模型 / 双模型策略切换。
- **产品落地**：以订单延迟送达为首个业务闭环，分为场景与目标、对话与后台、知识与接口、交付与验收。8 步对话样例逐项说明用户体验、角色职责、证据与当前实现边界。
- **实施全景**：从建库到试点验收的完整实施说明。包含全流程阅读地图、30 项能力对照、6 步建库与知识映射、模型路由决策与预算、交流状态与事件、工单后续闭环、运营工作台、系统数据流、成本及验收。能力表可按类别、状态和关键词筛选，每项附责任人、当前边界、下一步与验收条件。
- **对话试验台**：流式回复、来自执行事件的进度反馈、6 个独立场景、退款与物流催查确认 / 取消、催查状态查询、人工交接摘要。直接输入可继续当前会话。
- **知识与工具**：5 份可搜索演示文档、8 个工具及其执行权限、服务端策略说明。
- **流程评测**：12 个独立用例检查路由、来源和工具调用；这不是模型质量评测。

## 当前实现范围

模型使用确定性演示适配器，**没有调用真实 LLM**。双模型策略选择 `Demo Fast` / `Demo Deep`，单模型策略选择 `Demo Main` 的普通 / 深入配置；两者共用业务权限。操作追踪是结构化执行事件，不是模型思维链。展示耗时包含人为流式呈现延迟，不可据此比较真实模型性能。

所有订单和知识均为种子演示数据。身份固定为 `DEMO-01`，不是正式登录系统。订单、会话、工单、幂等记录保存在服务端内存，重启失效。浏览器 sessionStorage 仅存随机会话 ID，localStorage 仅存模型策略。不读取工作区的私人资料，不连接真实订单 / 支付 / 人工坐席。

- `SF-1024`：已签收 3 天，金额 ¥129，可进入退款申请确认。
- `SF-2048`：运输中，金额 ¥79，可查询物流；退款转演示人工工单。
- `SF-3096`：运输中，金额 ¥129，演示承诺时间已超过 36 小时、48 小时无新扫描，可核查并确认创建演示物流催查工单。阈值和时长均为种子演示设定，不是行业标准或真实承运记录。
- `SF-9999`：非当前演示身份，用于验证访问拦截。

每个新会话有独立订单副本。点击预设场景会开启新会话。确认令牌绑定会话、订单与金额；执行前重新检查资格；重复提交不重复申请。人工接管使未确认令牌失效，后续消息只追加到工单。退款申请创建不代表到账，也不执行真实支付。

物流催查另绑定确认时的物流快照，确认前不会创建工单；状态变化后需重新核查。确认成功得到 `LC-…` 编号，可继续查询“催查进度”；这只证明本地记录已创建，未联系真实承运商，不承诺送达日、加速或赔偿。

**目标方案与当前实现**：网页中的并发分析、分析中补充信息、会话上下文版本淘汰、真实模型与持久化是产品方案。当前聊天接口按会话串行处理，处理中暂不接受同一会话的新请求；不能把演示物流快照的确认校验等同于完整的异步会话协调。

能力状态按具体机制划分：**已实现**指当前本地程序可触发并核对的行为，可能仍只作用于内存与演示数据；**演示**指固定种子、模型替身或教学样例；**待开发**指尚未实现的目标功能。三者的数量不是生产完成率。实施全景中的接单、外部物流更新、解决、关闭和重新打开均为明确标记的虚构推演，不能当作现有工单状态。

8 步目标对话与运行方式也单独对照：部分自由追问当前会返回证据不足；自然语言“确认”不会直接建单，需要点击绑定令牌的确认按钮；短信补充目前未形成结构化、已核实的业务事实。新增页面补充这些实施要求，没有把相应后台功能伪装成已上线。

## 代码结构

```text
server.mjs            本地 HTTP、静态网页、流式 NDJSON API、会话锁
src/data.mjs          文档、场景、架构节点、工具目录、回归用例
src/adapters.mjs      意图分类和模型选择的演示替换点
src/engine.mjs        对话流程、业务权限、退款确认、幂等、人工交接
public/               原生 HTML / CSS / JavaScript 界面，无外部 CDN
public/product-*.js   场景产品方案与四标签展开视图
public/*guide*.js     知识/交流/运营/部署/验收说明与实施全景视图
public/capability-map.js  经过源码核对的能力与8步运行方式对照
public/assets/        已接入网页的两张架构图片
test/                 流程与 HTTP 集成测试
```

API：`GET /api/catalog`、`POST /api/sessions`、`GET /api/sessions/:id`、`POST /api/chat`、`POST /api/evaluate`。本地服务仅绑定 `127.0.0.1`，并限制本机 Host 与跨站写请求。

## 接入真实系统的后续边界

1. 用真实登录和租户鉴权替换固定演示身份，会话查询也必须检查所有权。
2. 把会话、订单操作与幂等键迁入数据库，保证事务一致性与重启恢复。
3. 在适配层接入模型的结构化输出 / 工具调用；服务端保留权限、确认和幂等控制，模型不得直接写业务数据库。
4. 把关键词检索替换为适用业务的全文 / 向量检索；文档保留版本、来源、可见范围和撤回能力。
5. 外部工具增加超时、取消、有限重试与故障交接。接入真实坐席系统与工单持有权同步。
6. 用脱敏真实对话比较解决率、错误承诺率、人工转接、P95 延迟和单次解决成本，之后再决定是否保留两个模型。

架构参考：[Building effective agents](https://www.anthropic.com/research/building-effective-agents)。
