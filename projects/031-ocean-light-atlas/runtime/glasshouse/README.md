# 傍晚海边玻璃屋

海的切片 / 空间试作 01。以「金色海面接住夕阳、暖灯留在玻璃屋内」作为画面目标。建筑、家具、海岸与纹理均由本项目程序化创建，未使用摄影背景或 AI 生成背景。

## 体验

在海的切片目录运行 `npm run dev`，打开 http://127.0.0.1:4197/glasshouse/index.html 。首页也有进入场景的卡片。已附带 bundle，预览无需安装依赖或访问外部网络。

用户授权用自己的0597人物，完成露台→海边岩石→坐下看海→起身返回，并配海浪、风与脚步声。[实际网页与带声音实录](seaside-review.html)，实时入口`?seaside=1`自动采用已认可的facial版本，原始文件和默认清单保留。

`rock-seat.js`定义一块特制岩石的坐面、方向、靠近点和时间；`seated-pose.js`在自己的骨架上协调骨盆、脊柱、手臂和双腿，手搭大腿，鞋底由原实际网格探针求解。`seat-coat.js`只按原色图/身体区域识别深蓝后摆，调整后摆权重并加入运行时折起形态，不改脸或磁盘GLB。`rocket-avatar.js`在坐姿叠加后恢复未被程序修改的动画姿态，防止暂停时骨盆位移叠加。坐姿/后摆是本场景运行时效果，没有新增到下载的基础GLB中。

`seaside-audio.js`复用本机earth-within项目已处理的CC0海浪/风实录，原作者、来源、处理与SHA在`assets/ambience/manifest.json`。海浪原录于海边，风原录于林间，用作较低音量过滤混音；不能说是本场景同期海风。脚步为本地合成，按实际触地分木板和沙地；环境音有静音/音量，暂停/隐藏时淡出，室内更闷更轻，人物讲解时降低。录音原速原调循环，没有逐浪头同步。

`npm run verify:seaside`实际完成带声音往返、坐面与鞋底采样、静音/音量/恢复，以及手机暂停与提前起身返回；保存WebM及检查数据。MP4需从该WebM显式24fps转码（非GPU性能指标）。`SEA_CAPTURE_ONLY=1`只做桌面完整实录与检查，另存capture报告，保留完整手机报告。仍是单人、单块岩石的定制姿态，程序化感及原生成衣服/手部细节仍可改进，不代表任意物体可坐或完整布料物理。

## 2.9：直接控制人物与台阶接触

选择「自己走动」，或直接按WASD/方向键，即可控制人物。按键方向相对当前镜头；拖动可调整观看方向，松键停止。手机展开面板选择「自己走动」后，面板会收起，按住左下角方向按钮移动。选择任一地点或「开始导览」可恢复带路。

玻璃墙、家具和露台边缘采用局部碰撞与地面高度约束；手动位置返回导览时，使用局部网格通路连接原路线。此处是本场景的简化行走区域，不是完整物理引擎或任意场景导航。

台阶的可见木板、支撑高度和脚部落点共用 `walk-surface.js`。`foot-placement.js` 在原动作之后调整髋/膝/踝，锁定支撑脚、让摆动脚先抬起再越过台阶边缘，按鞋底实际范围预留落脚空间，并降低骨盆以保持腿部可达。它读取真实蒙皮鞋底顶点检查接触，也覆盖门槛与湿沙。自动路线绕过底部台阶侧面；台阶跟随镜头从屋外侧观看，便于看清脚步。

这是网页运行时的脚部适配，不会把台阶动作写进下载的原始GLB。原模型、5段基础动作及许可保持不变。仍无手部碰撞、布料物理、完整相机碰撞或原型专属外貌。验证使用 `npm run verify:controls`，不以接触采样替代最终视觉判断。

## 实现与局限

`scene.js` 管理建筑、家具、天空、机位与交互。`coast.js` 统一沙岸高度与沿岸距离。`water-system.js` 管理海面、浪唇、碎沫、湿沙和室内水光。

- 海面在近处使用较密的网格，向外逐步放宽。几何长浪与像素级风纹共同决定法线；屏幕导数用于过滤远处高频细纹。水面使用波面朝向计算太阳高光，使用菲涅耳混合海水底色与反射。高光能量有艺术化的柔和压缩，未作真实太阳辐射标定。
- Three.js Water 插件提供反射相机与裁剪。自定义波面着色器替换其默认法线与光照；反射仍以平均海平面近似起伏水面。近岸透明浪层不会参与自身反射，避免纹理读写反馈。
- 近岸薄浪使用参数化 Gerstner 截面，近岸幅度和陡度随深度与风力变化，允许很轻的前倾。尚无流体破裂、体积水、泡沫粒子输运或真正的卷浪崩塌。
- 水光纹理由可变形的细胞边缘生成，共享风速、时间与日照状态；并非从实际海面法线逐光子追踪聚光。海面附近的投影相机和 768px 深度图负责真实几何遮挡，玻璃不作为不透明遮挡体。材质按表面朝向受光，因此向上的地板不会收到直接向上反射光。蓝调时太阳水光归零。
- 水光以材质漫反射的一部分叠加，受到接收物体颜色影响，不使用铺满屏幕的发光贴层。这个定向投影仍不能代替多次反射、完整光线追踪或物理焦散。
- 房间包含细框、滑门把手、木平台、支柱、台阶、布艺沙发、椅子、石桌、书、茶杯、盆栽、原创海景装饰画与暖灯。玻璃使用透射、厚度、折射率与环境反光；多层玻璃和斜视时仍有实时渲染局限。
- 3.1增加场景专用相机避障，使用几何包围盒近似；尚无完整物理碰撞或真实手机性能自动分级。本地浏览器的响应式检查不代表真实手机 GPU 性能保证。

## 构建

入口 `index.html` → `scene.bundle.js`。Three.js 0.187.0，esbuild 0.25.12。MIT 许可证随项目保留在 THREE-LICENSE.txt。

修改源码后，在父目录执行 `npm run build:glasshouse`。构建优先使用本目录可解析的依赖，本工作区可回用相邻 castle-at-dusk 已安装的依赖，不修改相邻项目。独立复制时，在本目录安装 package.json 声明的依赖，再执行 `npm run build`。预览使用已附带的 bundle，无需重新构建。

技术思路参考官方 [Three.js Water 示例](https://threejs.org/examples/webgl_shaders_ocean.html)、[GPU Gems：水面几何与法线](https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-1-effective-water-simulation-physical-models) 与 [GPU Gems：实时水光近似](https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-2-rendering-water-caustics)。本项目的微表面太阳高光、沿岸波形、室内聚光纹理与深度投影为针对本场景的实现，不冒称物理求解完成。
