# App 数据统计与趋势观察

每天保存 Apple 公开榜单及产品资料，观察哪些产品和方向出现排名提升、新入榜、评分新增与评分暴涨。覆盖中国、美国、日本、英国 App Store，以及美国、日本、英国 Google Play 免费榜与付费榜，各最多 100 条。产品和方向均支持平台筛选，排名与评分增量只使用同平台历史。

## 看报告

双击 `reports/latest.html`，或运行 `打开报告.cmd`。报告可离线使用，支持平台、市场、名称、方向、具体场景、核心能力和增长信号的组合筛选。“场景与能力”可下钻到成员产品；“产品趋势总览”提供产品×日期矩阵，点击后查看单产品近7/30天图表与明细；“评论统计”展示星级分布、关键词匹配、版本、日期和原文来源。`reports/latest.md` 是文字摘要，`latest.json` 可供后续分析程序或 AI 读取。报告只使用实际观测，首日明确显示“正在建立增长基线”。

也可以运行 `python preview.py`，在浏览器打开 `http://127.0.0.1:5227/`。这个只读预览服务仅提供当前 HTML 报告；每天报告更新后刷新页面即可。2026-11-15 已在浏览器实测搜索、四区筛选、组合筛选、空结果、增长信号与分页；验收记录和截图保存在 `reports/ui-check/`。

## 运行

需要 Python 3.10 或以上，以及 Node.js。安卓解析依赖通过 npm ci --ignore-scripts 安装（版本锁定于 package-lock.json）；Python 无第三方依赖。在本项目目录运行：

```powershell
python -m app_radar collect
python -m app_radar status
python -m app_radar report
python -m unittest discover -s tests -v
```

也可从任意目录运行：

```powershell
python run.py collect
```

`collect` 退出码 0 表示完整成功，2 表示部分缺失或采集失败，1 表示配置或运行错误。每批请求间至少间隔 3.2 秒，瞬时网络错误会有限重试。采集需要电脑联网；Codex 工具的网络沙箱可能需要正常的联网权限。保留证书验证，不使用私人登录态。

每日执行由本聊天的 Codex 自动化安排在北京时间 09:00。电脑和 Codex 的可运行状态、网络及任务权限会影响实际执行。手动运行与每日任务使用同一个命令；同一时刻只允许一个采集进程，进程异常退出后操作系统会释放锁。

## 保存什么

- `data/radar.sqlite3`：逐日产品快照、地区榜单、采集结果与错误。
- `data/raw/日期/地区/`：每次真实响应及来源 URL、采集时间、SHA-256，失败前取得的原始响应也保留。
- `reports/日期.html / .json / .md`：每日报告；同日重跑更新当天报告和 `latest`。
- `data/logs/`：可选的 `run.ps1` 日志入口所保存的终端日志；该入口仅在本机允许运行 PowerShell 脚本时使用，无须为它更改执行策略。日常使用上面的 Python 命令即可。

同日重跑以最新成功榜单更新榜单成员，不追加重复名次；失败重试保留当天之前已取得的有效观测。当天有效的评分数不会被后续缺失字段抹除。离榜 App 默认继续追踪 30 天，每区最多刷新 1000 个（当日榜单产品始终保留），超过上限会在质量说明中列出。系统不自动删除历史、迁移其他资料库或清理磁盘。

## 增长判断

| 指标 | 条件 |
| --- | --- |
| 排名上升 | 与昨天同地区、同榜单的成功观测比较 |
| 新入榜 | 昨天完整榜单未出现、今天成功榜单出现；首次收录不能判为新入榜 |
| 新增评分 | 同一地区连续两日的累计评分数之差；缺失或评分数回退时留空 |
| 评分暴涨 | 当天新增至少 20，达到前 7 天日均的 3 倍；需要 9 个连续日期的完整观测，基线须大于零 |
| 方向增长 | 在同一地区和方向内按 App ID 去重，统计样本量、可比较量、排名上升和评分增长的产品数 |

所有日期按北京时间计算。没有历史不补造数据，缺日不补零、也不把多日增量冒充单日增量。Apple 榜单是来源发布时刻的快照，源更新时间和本地观测时间分别记录；源更新时间早于 36 小时或明显晚于当前时刻时不作为今天的有效榜单。

方向规则在 `directions.json`：优先使用 `overrides` 内的 App ID 人工指定，其次匹配名称关键词，未命中则使用商店分类。名称匹配是初步归类，可能误分；报告始终显示分类说明，规则修改后可运行 `report` 重新分类当前比较窗口。

## 范围与限制

这是榜单样本监测，不能代表全量 App 市场。已接入 iOS 和 Google Play；不包含畅销榜、全分类榜、广告库、真实下载量、活跃用户和收入。评分新增和排名只作增长信号；机器人评分、商店数据修正及更新延迟都可能影响信号。

更多分类榜、手动关注名单和付费第三方数据可以后续通过独立数据适配器扩展。收入估算需要可靠校准数据，当前版本不输出收入数字。

## 安卓数据口径

Google Play 使用 google-play-scraper 解析公开商店榜单和详情。保存的是解析结果、商店链接、观测时间及哈希；来源没有提供榜单更新时间时保持为空。解析库不是 Google 官方API，商店页面改版可能导致失败；错误会保留在报告中。详见 https://github.com/facundoolano/google-play-scraper 。

安卓评分可能是全球汇总，同一 App 的不同国家页面不能相加为新增用户。排名按所在市场比较，评分变化按同平台同市场连续观测计算，作为商店信号。安卓ID使用 play:包名，榜单使用 android- 前缀，与现有 iOS ID、历史记录互不覆盖。跨平台同名产品不自动合并。

可使用 python -m app_radar collect --android-only 仅刷新安卓并保留报告内已有的 iOS 观测。每日9点任务运行普通 collect，一并刷新两平台。Android 首日单独建立基线。

## 场景与核心能力标签（2026-11-20）

`directions.json` 同时维护 `taxonomy_version`、`tag_overrides` 和 `tag_rules`。场景回答“用户在什么情况下用”，能力回答“产品具体做什么”；每个产品可以拥有多个标签。优先使用以平台独立 App ID 为键的商店说明核对项，记录来源链接、核对日期和限制；其余名称规则标记“待复核”，支持 `exclude` 排除歧义名称。宽泛商店分类不自动生成能力，未匹配产品保留“待补充”。商店说明核对代表核对开发者声明，不代表实测功能或增长归因。

HTML 产品表显示标签、依据与说明，可同时筛选场景和能力，搜索也包含标签。场景与能力页签支持平台、市场、标签类型、最少样本、关键词与排序；默认至少3个样本，选择“全部”可查看单产品线索。点击标签自动带入同平台、同市场的产品筛选。

JSON 新增 `tag_growth`、`tag_coverage`，每个产品新增 `scenes`、`capabilities`、`tag_evidence`、`tag_status`、`tag_note`。聚合限定同平台同市场，每个标签内按 App ID 去重，多标签分组不能相加。排名上升率使用实际连续两日同榜排名可比产品为分母（离榜、新入榜、只有评分可比的样本不放入分母）；新入榜和评分增长分别列出。少于5个样本标记小样本，不解释为行业趋势，也不按国家合计安卓评分。

规则调整后运行 `python -m app_radar report` 即可用已有观测重建当前报告，不需重新联网采集或迁移数据库。分类版本保存在报告中；规则变化本身不计为市场增长。历史日的旧报告保留，除非明确指定 `report --date YYYY-MM-DD` 重建该日。标签覆盖率与待补充数量始终显示，避免将有标签样本当成全量市场。

验证：`python -m unittest discover -s tests -v`，`node tests/report-dom.mjs`，`node tests/tags-dom.mjs`。后两项运行真实报告的 DOM 与事件逻辑，不替代浏览器视觉验收。

## 评论统计与历史趋势（2026-11-22调整）

系统定位为数据采集、统计和展示工具，产品价值、需求解释与商业判断交给人。当前报告不生成或载入机会假设、切入判断、最小原型或建议。旧版判断文件和历史报告作为历史资料保留；重建当前报告不会删除数据库或原始响应。

`collect`仍在榜单采集后进行有边界的评论采样：每个平台最多6款，每款最多100条最新评论，仅统计近90天。持续跟踪名单、按市场补充和增长信号排序仅用于控制采样范围，不代表产品推荐。采样产品、选取原因、空结果、无近期样本和失败分别展示；并非全量、随机或具有市场代表性的样本。

评论按ID与重复正文去重；只关联当前run成功请求的归档路径，同日重复采集不将旧批次混入当前样本。中英日规则只保留匹配表达、标签和来源，分别统计4—5星、1—2星和不限星级的改进请求表达。关键词匹配可能存在误判；未匹配不代表没有相应反馈。星级占比仅为当前样本分布，不解释为总体满意度，评论量不等于评分总数。

“评论统计”支持平台、市场、产品、关键词主题筛选；样本星级分布随产品范围变化，评论表另支持星级过滤与分页。报告仅展示短摘录、日期、语言、版本和商店来源。完整正文保存在本地归档和数据库，历史研究判断JSON不再加载。

“产品趋势总览”默认展示中国iOS免费榜近7天“期间曾上过榜”的全部产品，以图表简报为主。先给出实际日期、观察池/筛选后/图表数量和客观摘要，再展示四项统计卡、报告日产品状态占比、持榜天数分布、名次起止日变化条形图及7日新增评分条形图。多产品排名折线继续保留，勾选列表和逐日数据明细默认折叠，减少汇报主视图中的操作与表格。

所有图表采用同一平台、市场、榜单及筛选后的展示范围。状态图按报告日明确在榜、完整榜未出现、未知三组统计，不把离榜当成下架。持榜图按已观察到排名的天数计数，并将含未知日期的产品单独标色；超过10个实际日期时用每5天分组。名次变化图只在首尾两日都有效且至少有两个日期时计算，按绝对变动展示前8款，中心为0、左降右升，并列出起止日名次和不可比数量。评分条形图按已记录条数展示前8款，默认仅完整7/7天，部分合计另行切换、逐项标记有效天数，不混成同一时长比较。数值摘要由真实观测直接统计，不推断原因或商业价值。

展开后的变化列表中，每行一个App，列出报告日排名或状态、排名起止日变化、统一第1—100名的小折线、持榜天数、7日新增评分与有效天数。可切换逐日对照表：每列一个日期，支持排名、每日新增评分、累计评分。点击产品进入详情，返回后保留筛选。

观察池可选“报告当日在榜”或“期间曾上过榜”。后者从所选日期的真实成功榜单中取App ID并集，包含今天已离榜、甚至没有当日产品快照的历史产品；按期间最好名次、最近上榜日期排序。可显示前10/20/50/100款或全部，并按报告日的当前在榜、已确认离榜、状态未知筛选。候选池总数、状态筛选后数量和实际展示数量分别写明。逐日表、变化列表和多产品对比图使用同一观察池；不把历史池数量当成当日采集量。

持榜天数为所选实际展示日期内真实有排名的天数，同时显示可判定天数/展示天数及未知天数。明确有排名或完整前100榜未出现时才可判定；短榜未返回、请求失败与缺失均记未知。小折线横轴对应同一批实际日期、纵轴统一1—100名且第1名在上，缺失断线，不补零、不填第100名。排名变化仅在起止日都有排名时计算。

7日新增评分固定为报告日及之前6个日历日，独立于排名的7/30天窗口。只加总同平台同市场连续两日可计算且非负的评分增量；展示有效N/7天，未满7天注明“部分合计”。没有有效日显示“无可计算数据”，7个真实零增量显示“0条、有效7/7天”。累计数回退、缺失不补零，也不跨缺日计算。该数不是下载量，不跨市场或平台累加。

“多款App排名对比”与总览使用同一平台、市场、榜单、观察池、报告日状态、展示数量和日期窗口。每条线对应一个勾选产品，默认前5款、最多10款；支持搜索候选、清空和重新选择前5款。线条颜色与线型、编号图例对应产品，取消勾选不改变其他已选产品的颜色；切换平台/地区/榜单隔离选样，缩小前N范围会移除范围外产品，切换日期或表格评分指标保留选择。

对比图纵轴排名倒置，第1名在顶部。默认按所选产品范围适配（明确显示1至多少名），也可固定为完整1至100名；缺失排名断线，保留按产品和日期的状态说明。点击图点、键盘聚焦后按回车，或选择日期，可查看所有已选产品当天的准确名次。对比图始终展示排名，表格可独立切换新增/累计评分；不混合不同市场或榜单的名次。

“单产品详情”展示当前已收录产品的近7/30天历史，按平台与市场分别选取，可从产品表直达。图上方显示截至报告日期的免费榜/付费榜名次、与昨日的名次变化、累计评分和今日新增评分；没有当日数据时不拿旧值冒充当前值。实际展示日期、日历天数与各指标有效天数单独列出，不把近30天窗口当成已有30天记录。

排名使用折线，第1名在顶部；评分日增量使用从0起算的柱状图，坐标明确标明日期、名次和数量单位。缺失不补零：完整前100榜单未出现、短榜未返回、榜单观测缺失，以及评分当日缺失、前日缺失、数值回退，分别按日期解释。无排名记录的系列不显示图例。图点和柱子可点击、键盘聚焦后按回车查看当天数值，日期选择器提供相同操作；手机按实际容器宽度绘制，避免坐标文字随桌面SVG等比缩小。

JSON保留`research`字段和旧主题键`needs`、`pains`、`requests`以兼容现有读取方，但语义为关键词匹配分组，`research.mode=statistics`，`opportunities`和`briefs`为空。新增`trends`保存最近30天内的日历日期、平台市场独立的逐产品明细和计算口径。`report`仅读取现有数据库重建，不重复联网。

每日任务仍为北京时间09:00，已调整为统计、趋势和数据质量核对，不再自动写研究判断。公开网站是单独发布的固定快照，本地每日任务不会自动更新网站。

## 快速理解与核对（2026-11-22）

默认只展开平台、市场、榜单和时间四项筛选，产品范围、报告日状态和数量收进“更多筛选”；当前实际范围始终写在简报上方，限制数量或状态时说明筛选前后的数量，可一键恢复默认范围。首页标明实际榜单记录天数、完整榜天数、评分可计算满7天的产品数，近30天尚不足30个日期时明确说明。

四个数字卡分别展示本页产品数、排名上升产品数、每个展示日期都有排名的产品数和评分数据完整的产品数；卡片可跳到相应图表。每张图先用一句数据描述解释，再给图形和口径。排名升降可切换全部、只看上升或只看下降，并把图中前5款直接带入多产品逐日曲线。曲线区明确区分候选数和当前已勾选的线条数，搜索和勾选后同步更新。

从总览的图表或表格进入单产品详情时继承7/30天窗口，详情标题显示产品名，全市场汇总卡不再混入单产品语境；返回保留原筛选。数据缺失、短榜与部分评分合计仍保留原统计规则，不生成商业判断。浏览器验收记录保存在reports/ui-check/quick-understanding-20261122。

手机端默认收起整个筛选区，优先展示当前统计范围、覆盖与关键数字；展开后仍可调整全部范围。桌面端默认展开四项常用筛选。没有匹配产品时自动展开筛选区，便于恢复默认范围。
