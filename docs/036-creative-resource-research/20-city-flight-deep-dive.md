# 20｜Muse＋城市3D数据：小柚外景底稿与地标验收

研究日期：2026-11-22。已核对大阪城与东京站两段原片共13处、引用作者过程文和官方资料；未导入城市数据或生成小柚外景。

对小柚的价值是建立可重复取景的城市外景底稿：让街区、地标、视角和构图先有明确依据，再选择直接3D渲染或生成式润色。它适合城市题材片头、转场和口播配画；生成画面必须重新检查建筑、钟面/顶饰、道路与背景关系。它没有解决小柚的脸、口型、角色表演，也不能把生成航拍当作实拍或当前城市事实记录。

## 来源纠正

noel_ai_lab自述用PLATEAU数据在Blender出静帧，再由Muse生成大阪城视频；未取得其回复教程、数据年份/网格、工程或任务日志。成片约30秒，不能据此认定制作只花30秒。补读引用作者Zimo的2026-11-05过程文，确认其东京站路线还包含Muse Image改写静帧，再交Muse Video；这段补充不自动代表大阪城作者采用相同参数或步骤。

## 原片怎么核对

2026-11-22核对2026-11-12公开镜像快照；两条X原帖本轮直读403。浏览器用原生视频时间轴暂停取样：大阪城7处、东京站6处，共13处，最终保存时readyState=4；截图1280×720含播放器黑边。原帖解码1152×768、30.083333秒；引用片实际1080×720、10.112秒（快照尺寸1152×768，所选MP4为1080×720）。秒数为currentTime近似定位，未标定切点/相机轨迹、听审或量测几何/建筑一致性；原视频未下载或转码。

### 大阪城开头：明显的模型底稿外观

约0秒可见贴图城堡、简化周边建筑、灰色平地和块状物体，环境信息比后段少。它显示了模型式底稿的起始外观；没有对应工程和数据包，不能只凭此帧鉴定数据版本、LOD、建筑完整度或转换方式。

### 大阪城中后段：护城河、城堡近景、屋顶与广域俯瞰

约5秒可见石墙、树木和水面，10秒为城堡与广场，15秒接近建筑立面细节，20秒越过屋顶望向公园和城区，25至30秒为更宽的俯瞰。可借用“地标建立→细节→空间展开”的表达；未恢复真实轨迹或逐帧检查，不确认精确环绕360度、一镜到底、单次生成或所有建筑保真。

### 东京站：白天到夜景，顶饰与立面外观变化

0至4秒从较宽正面附近视角接近圆顶区域，6至10秒进入夜景照明，顶部圆形细节、窗和立面外观发生变化。作者称钟表逐渐增加；本轮保留该反馈，但未做同一表面区域追踪、数量标注或真实建筑照片对照，不把更多圆形物一律判成新增钟表。

### 两段作品是不同示例，不能当作对照实验

大阪城约30秒、东京站约10秒，场景、构图、时间变化与生成设置不同。两者帮助认识从模型底稿到生成画面的表达能力及风险，不能比较Muse的成功率，也不能把东京站问题证明为PLATEAU数据错误。

## 具体分析

### 先分清四个角色：城市数据、3D软件、Agent与生成模型

PLATEAU提供城市数据；Blender负责场景、材质和相机；Muse在帖子中编排工作；Muse Image/Video会重新生成画面。引用作者的过程文补出了“Blender渲染→Muse Image静帧→Muse Video”这一段。三维工程的几何与相机信息不会因为渲染成图，就自动成为视频生成器的硬约束；也不能把这里的Muse与小柚口型链里的MuseTalk混同。

依据：Zimo本人11月5日过程文；PLATEAU导入教程；Meta的Muse Agent介绍及Image/Video官方摘要。

### 空间依据要在数据阶段留档，不能只保留一张漂亮图

小柚外景底稿应记地区、数据年度、网格/建筑标识、LOD与纹理来源。只取需要的分块，保留转换与机位记录，之后才能复用取景或追查变化。地理数据转进3D软件时还需核对坐标系、单位、轴向和局部原点；错位、远离原点或材质路径丢失都应先在底稿阶段排查。本轮没取数据，不能断言原作这些步骤已经正确。

依据：PLATEAU开发图解说明分块与坐标；TOPIC8说明OBJ转换、轴向/单位与材质文件结构。

### LOD和贴图决定底稿能提供什么，缺失细节不能由“真实数据”担保

低细节模型和贴图缺失会使近景显得简化，近看窗、屋檐或顶饰时尤其明显。官方影视教程也需要补材质、局部几何、灯光和环境。AI补出的植被、人群、纹理或新结构应与源数据分开标注，不能自动当成实景事实；数据本身也有采集年份和抽象化边界，不是城市的实时完整复制。

依据：PLATEAU LOD说明、FAQ的更新/抽象化说明和TOPIC26的场景细节制作；原片0秒与后段外观差异。

### 照片化静帧与视频化是两次验收，错误可能提前出现

引用作者明确先把Blender渲染交Muse Image，再拿改写后的静帧生成视频。应在渲染→改写静帧时先比轮廓、建筑相邻关系和关键细节；通过后，再验视频里的持续变化。若第一张图已改错，再好的视频一致性也只会稳定地延续错误。没有中间资产，无法把原作某个变化准确归因给图像或视频阶段。

依据：Zimo过程文中的两次生成与改机位描述；本轮未取得中间图/任务完整对照。

### 直接3D渲染与生成式润色，按用途选择

需要明确建筑关系、相机路线或多镜头复用时，可先选择已核对场景的直接渲染，再做有限后期；这保留工程控制，但不补足源模型缺失的真实性。需要氛围配画时，可试生成润色，接受它可能重新解释空间。仅提供首尾图或提示词也不保证中间经过预期路线，必须按实际工具控制入口和成片核验。

依据：PLATEAU官方TOPIC26有相机位置关键帧、渲染与合成流程；两条路线为本项目建议，非原作复现。

### 地标QA要看数量、位置、形状与时间，别只看是否像某座城

对城堡看层级/屋顶、入口、石墙水面和周边地标；对车站看钟面/顶饰、窗列、圆顶、出入口与背景建筑。固定区域在相似视角下比较，遮挡后重现也要查。相机换角度会让原本看不到的面出现，单凭“画面里多一个圆形物”不能算幻觉；本条把作者的钟表反馈和本轮实际检查分开记录。

依据：两段原视频13处；地标/时序QA模板为本项目方案，未完成逐区域计数或几何量测。

### 30秒片长不是30秒制作，开源数据也不等于零总成本

原帖视频实际约30.08秒，只有成片时长可核对。数据准备、转换、材质、渲染、生成、挑选与返工都要计入工时。Zimo文中8GB环境和慢渲染只是个人记录，不能当成通用配置或速度结论。使用具体城市数据时保留该数据条目的来源、年度与适用许可；本轮未测试Muse账号、额度、安装或本机性能。

依据：浏览器时长；作者过程文的环境自述；PLATEAU FAQ列多种开放许可和数据年度检查入口。

### 小柚先做一段5秒城市配画，人物和城市分别验

优先为城市题材短片做建立镜头或口播B-roll：先选一处地标、一种小幅移动和统一白天光照。A保留直接渲染，B用相同起始构图做一次生成候选，对比地标改写、路线偏差和总返工。两者控制粒度可能不同，记录这种差异，不冒充严格模型基准。首轮不加小柚人物，环境通过后再接人物，分别查身份、光照、比例、接地和遮挡；收益待实际结果决定。

依据：本项目5秒双路线方案与资产/QA模板；本轮未生成城市配画或小柚合成。

## 数据与场景交接

| 交付层 | 必要内容 | 验收 |
|---|---|---|
| 数据来源 | 城市、数据年度、分块/标识、LOD、纹理来源和适用许可 | 核对真实条目与采集范围；不猜原作数据年份 |
| 场景工程 | 转换方式、单位/轴向/原点、材质路径、地标与周边关系 | 模型数量/缺失、贴图、位置和近景细节；保存可重开工程 |
| 相机与意图 | 起止构图、观察目标、移动方向、时长、光线与画幅 | 工程参数与实际视频表现分开；不把提示词当硬路径 |
| 中间静帧 | 源渲染、生成改写版、版本与参考关联 | 两版先比地标轮廓和相邻关系，静帧没通过不升视频 |
| 视频与地标 | 原始输出、失败时点、钟面/顶饰/屋顶/窗列和背景记录 | 同面/近角度逐段比，区分遮挡出现与真正新增 |
| 小柚合成与成本 | 环境通过后再接人物；比例、光线、接地、遮挡和总工时 | 环境/人物分别判定；当前无样片，不记通过 |

## 5秒首轮候选（尚未执行）

以后用一处地标做5秒城市配画，比较直接渲染与生成候选在地标保留、运动表达和返工上的差别；本轮只交付研究与模板。

1. 先定位地标与分块，确认模型/纹理和坐标正确，保留场景。
2. 用少量静帧检查起止构图、裁切及可见地标，不先做长片。
3. A设置相机并直接渲染；B以同一起始图做生成候选，记实际输入差异。
4. 若B包含图像改写，先验静帧，再进入视频，避免带错图继续生成。
5. 逐段核对相同区域和近似视角的屋顶、钟面/顶饰、窗列、路网/水面与背景。
6. 记录时长、失败、总工时/费用，先决定环境路线，再接人物。
