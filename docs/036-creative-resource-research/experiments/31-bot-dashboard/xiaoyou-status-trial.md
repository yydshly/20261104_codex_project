# 小柚制作看板 · 单镜头试填表

这是本地回放用的假设材料。目标是在不翻聊天的情况下找到等待原因、负责方和正确版本。

## 每张卡写什么

- 镜头、工序、版本、尝试编号和最后更新时间
- 排队、处理中、等待输入、失败、待验收或已交付
- 需要谁确认，以及要看的具体问题和时间码
- 可打开的本地产物、验收记录和交付记录

| 工序 | 正常产物 | 待确认或异常的例子 |
| --- | --- | --- |
| 底片 | 已选视频和音频版本 | 缺源音频，等选片人补入 |
| 口型 | 与源音频对应的候选 MP4 | 处理失败，显示本次原因与重试编号 |
| 质检 | 对应版的时间码和验收结论 | 2.5 秒嘴缘闪烁，请确认 A 或 B |
| 交付 | 通过的 MP4、字幕与交付记录 | 新版待验，旧批准还留在旧版 |

## 五种回放

| 输入 | 预期看见 |
| --- | --- |
| 源音频缺失 | 等待输入，列具体文件、确认者和最后更新 |
| 口型 v02 第 1 次失败，第 2 次成功 | 当前为待验收，仍能追溯第一次失败 |
| 第 1 次失败重发或迟到 | 不重复计数，当前版本不回退 |
| v02 已通过，又生成 v03 | v03 待验收，v02 原审批和交付记录仍可查 |
| 无新事件超过本轮约定检查时长 | 显示待核实和最后更新时间，保留上一次状态 |

用事件本身携带的尝试号和有序记录判断新旧，接收时间仅作同步参考。数值和时长由试填时现场记录，当前没有团队效率测量结果。

## 记录结果

- 从页面定位待办、打开正确版本的时间
- 是否出现误报、重复提醒、无产物标已交付
- 有哪一条状态没有可追查的依据
- 是否需要跨设备或和别人共享
