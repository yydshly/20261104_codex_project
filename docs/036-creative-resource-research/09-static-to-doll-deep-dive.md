# 09 从静图走向可复用的轻动角色

核对日期：2026-11-21。Doll Studio资料固定到提交 `127968436dca6d564b6075de94259679e4f17c43`。

这条对小柚的价值是把一张成熟插画延展为可维护的轻动角色：先拆层和补画，再校正部件、眼线与头颈点，最后按发内容或交互的需要选择交付。Doll Studio可补充第06条“角色资产从哪里来”的思路，但.doll与LivLiv/Cubism格式应分别适配。当前已核对原作与实现说明，没有小柚模型、导出回读或互动收益的实测。

## 本轮新增的实现线索

原片并非只有角色成片：可见Doll Studio、lunar_maid_layered.psd、19部件及Auto-rigged标签。本轮定位到作者公开仓库，确认当前流程为分层PSD→自动绑定→.doll/独立HTML，不依赖Live2D Cubism。原帖称“Live2D”保留为作者用语，不能据此认定.moc3兼容；引用四图也不自动构成四组明确的转换前后对照。

原帖较早把效果称为Live2D；本轮通过录屏中的Doll Studio名称定位同作者的公开项目。软件名、PSD及部件界面相互对应，但没有原录制工程，不能保证当前提交的每项功能都在原片录制时可用。

## 原作效果

### 四张静图共有“人物近景＋一侧留白”的构图

四张分别是蓝发兽耳女仆、橙发花饰、银紫发角饰、金发王冠角色。脸和装饰是主要视觉信息，留白方向有左有右。这是构图观察，不证明其传播数据、原创权利或每张都已有动态模型。

### 录屏使用了已经分层的PSD

顶部文件名为lunar_maid_layered.psd，左侧标19 parts，并列出前发、嘴、鼻、左右眼睫/虹膜/眼白等部件。这表明展示对象已进入部件化阶段；录屏未展示从一张平面图拆成这些图层的全过程。

### 可见小幅头倾、视线和发丝位置变化

多个时点的头部、眼睛方向、发丝边缘和界面参数数值不同。可把它概括为轻动预览，不能据几处暂停画面量出动作精度、自然度或证明所有可见按钮都工作正常。

### 口型、面捕和导出入口出现，但没有完成验收

界面有Idle motion、Follow cursor、Lip sync、Face tracking、Export及桌宠按钮。原片取样没有导出文件再打开、面捕输入与角色并排，或中文语音对齐记录，不能把入口可见写成这些功能已经实测通过。

### 静图与录屏缺少明确的一一映射

录屏展示银紫发月饰女仆，与引用四图的发色、装饰和服装组合并非已给出同一底图的转换记录。原帖没有指定哪张对应这份PSD；不能据引用关系断言四图都已无损变成模型。

2026-11-21在浏览器逐张打开引用帖4张1672×941原图并确认解码完成，另在原始MP4时间轴暂停核对0、2.518924、5.051362、7.568264、9.543333秒，交付视频截图readyState均为4。来源元数据9.535秒，浏览器时长9.543333秒。截图为1280×720浏览器显示，不作为原图逐像素量测；未下载或重绘原始媒体。X正文直读403，文字沿用2026-11-12快照。项目资料另固定到2026-11-10的提交，不把后续功能全部倒推为录屏时已可用。

## 具体结论

### 1. 实现已定位：Doll Studio，不把俗称当作格式

录屏的软件名、分层PSD和部件界面与作者link-ding/doll-studio项目对应。当前README明确不依赖Live2D或Inochi2D，使用自有.doll格式；因此旧判断“只有成片、无实现线索”需要更新，但不能由此认定原片可导入Cubism生态。

依据：原片界面；作者仓库固定README、FORMAT及src/format.js。

### 2. 平面图到分层资产是单独一道工序

Doll Studio读取分层PSD，按图层名称识别部件再绑定。README把单图拆层交给See-through或独立image-to-psd流程，并要求补足遮挡区域。小柚先检查前后发、眼白/虹膜/眼睫、脸与颈部等层的边缘、透明度和遮挡补画，不把“自动绑定”理解成自动完成所有美术准备。

依据：项目README的Making the PSD/Artwork requirements；Live2D官方分层教程仅作为通用美术准备依据，不代表两者格式相同。

### 3. 自动绑定之后仍要修部件和控制点

文档允许更改识别错误的部件类型，校正头中心、头半径、颈枢轴与眼睑线，并清理散线和错层。验收应看转头时脸边/发际是否露洞、眼睫与虹膜是否错位、颈部和饰品是否脱节；增加动作之前先处理这些问题。

依据：项目Workflow及图层清理说明；本轮没有导入和修改PSD。

### 4. 模型交付与会动视频是不同成果

.doll v1是自带PNG贴图等信息的JSON模型，包含网格、绑定和物理设置；当前导出还包括独立HTML。公开README同时把表情预设、动作录制和手工网格/关键形变编辑列为未完成项。若只要发短视频，应另做录屏或适当的视频制作流程；不能把模型导出当作已内置完整视频剪辑。

依据：FORMAT、src/format.js和README Export/Not done yet。

### 5. 口型与眨眼要有对应资产和运行驱动

当前.doll格式有闭嘴和可选半开、张开、圆/扁等嘴形，缺失嘴形会回退；自动生成嘴形在文档中为默认关闭。小柚需检查眨眼形状、口腔、牙齿、嘴帧与中文音频，再判断是否可作回应头像。原片出现按钮和参数不能替代声音与表情的实际对照。

依据：Doll FORMAT Mouth shapes；Live2D SDK眨眼/口型文档用于说明Cubism同样需要参数与驱动，而非验证Doll兼容。

### 6. 与第06条可衔接思路，文件格式仍需分开

Doll README说明待机、声音和面捕代码改自LivLiv Player，所以两条研究有直接技术关联。小柚可借它完善资产准备，再选择对应播放器；.doll不是.livliv或.moc3的同义词。若明确要Cubism交付，应另验.cmo3源工程、.moc3/.model3.json、贴图以及所需动作/物理文件。

依据：Doll THIRD_PARTY_NOTICES及FORMAT；Live2D官方文件类型与嵌入数据文档。

### 7. 内容价值和可用性需要各自验证

把成熟小柚插画做轻动版，可作为封面、待机展示或后续交互资产的候选；这属于应用判断，原帖没有提供互动率或成本收益。首轮只选眨眼和轻微转头，按实际尺寸检查身份、边缘、首末衔接和导出回读，再决定扩展口型/面捕。静图、拆层模型与传播结果分别留证。

依据：四张静图与原演示，结合本项目的待执行验证设计。

## 对小柚的直接价值

保留成熟插画的脸、服装和版式，先尝试眨眼和轻微转头，能得到另一种待机或内容呈现方式。更重要的是把母图、分层、绑定和运行文件分开保存，让之后修边缘、改参数有明确落点。这是候选应用价值，原帖没有证明互动或转化提升，也不能把插画效果直接外推到写实小柚。

## 两条交付路线

### 轻动内容路线

只希望把成熟小柚图延展为会动展示，用于封面、短内容或待机画面。

1. 先选两项自然动作，保持人物身份和版式。
2. 选择合适的制作/录屏方式，保留静态基准与实际输出。
3. 按发布尺寸回放，检查首末衔接、脸部与发丝边缘。
4. 如果要比较传播效果，单独记录静图与动态版的曝光条件，不从观感直接推断提升。

限制：当前Doll文档不提供已完成的动作录制功能。；原片不是无缝循环与传播收益的证明。

### 可复用角色资产路线

需要以后改参数、驱动口型或嵌入网页时，先验收资产与对应播放器。

1. 准备分层PSD，核对补画、部件命名与修图。
2. 在后续试验中校正绑定、眼线与头颈点，保存可编辑材料。
3. 导出.doll并回读，再检查独立HTML或对应播放器。
4. 有明确需求后另测音频/面捕；若要求Cubism则走对应工程和SDK交付。

限制：本轮未运行编辑器、导出或任何设备驱动。；项目原始代码整体许可在本轮所见根目录/README中尚不明确；依赖Apache不自动覆盖原始工程，复用发布前应确认。

## 格式和许可边界

Doll v1是带贴图、网格与绑定的JSON模型；LivLiv和Cubism分别有其自身模型入口。Cubism官方文档所列.cmo3源工程与.moc3/.model3.json等运行数据，是另一套交付要求，不能把“看起来像Live2D”当成兼容证据。

当前仓库第三方通知说明LivLiv/MediaPipe代码的Apache来源，但本轮所见根目录和README没有明确原始工程整体许可证。这里只记录该缺口，不把它断言为任何具体用途已获准或被禁止。示例图片、拆层服务和工具代码的条件分别确认；本轮没有安装技能、下载程序、上传小柚图片、启用设备或修改桌面/通知设置。

## 小柚的首轮验证

1. 确定需要保留的脸、发型、服装、饰品和留白，写明首轮仅两项动作。
2. 拆层并单独检查隐藏区域与透明边缘；保留工作稿和导入稿，区分底图与补画内容。
3. 在后续试验中检查自动识别，校正头颈点、眼睑线和错层，不断扩大动作前先修静态外观。
4. 分别检查眨眼全过程和有限转头，再回看两者同时发生的边缘与身份变化。
5. 按真实需要导出：模型路线回读.doll并另验HTML；内容路线检查视频连续播放和首末衔接，不假定有内置录制。
6. 记录失败时点、人工修图/绑定时间和回读证据，再决定是否扩展口型/面捕或做传播对照。

- 原图、分层PSD、模型与输出之间能追溯；不将四张引用图当作已知输入输出真值。
- 小幅动作无明显脸型漂移、眼睛错层、发际露洞、饰品断开或颈部切口。
- 眨眼形状与眼白裁切自然；转头幅度按素材能力决定，不保证任意角度。
- 模型能在对应播放器重开，HTML或视频在目标环境实际可用；格式兼容不靠后缀猜测。
- 若做循环，记录首末姿态和速度的衔接；仅首末截图相似不能代替连续回放。
- 传播收益、耗时和成本未测保持空；reproduced和个人digested分别记录。
