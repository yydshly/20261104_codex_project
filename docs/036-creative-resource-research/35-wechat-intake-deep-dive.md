## 原帖与证据

22 张图来自原帖所指长文。原文描述 v0.1.4 的 macOS 实机路径和 Windows 未签名包，‘只有 Mac 能用’过于笼统。

本轮只读核对 22 张原图和公开发布信息，未安装软件、连接账号或发送聊天。

## 具体分析

### 先确定用户选了什么

图中可见分享入口、指定 Bot、携带 ZIP 的悬浮输入框与上传进度。附件少没少，取决于导出包里有没有，发送前核对清单。

依据为 原文与文章图 2–4。

### 发送记录分已发与未知

作者描述先存本地、再排队发送、结果不明停下。用消息 ID 或本地记录核目标端是否收到，之后才能决定是否重试。

依据为 原文的发送记录段与图 8–9。

### 归档和摘要是接收方的职责

工具传递材料。云端 Bot 可解压和提炼，是否入库由它另配规则。小柚可先把讨论摘录转为镜头、待确认和证据链接。

依据为 原文和接收端示例。

### Windows 可用方式有差别

v0.1.4 有未签名 Windows x64 ZIP，实机完整转发流程待验。读到的现行说明还区分：macOS 有独立分享组件，Windows 有文件入口和单一目标选择。

依据为 固定发布页 / 仓库平台说明。

### 从脱敏样本验证

转发给 Bot 就跨出本地范围。作者另外说明 CLI 模式可能在本机保存明文登录信息。小柚在 Windows 首轮用本地脱敏 ZIP 和人工确认，核收件范围后再决定是否接云端。

依据为 原文 / 仓库使用边界。

## 小柚的落地步骤

| 步骤 | 怎么做 | 要检查的事 |
| --- | --- | --- |
| 选择资料 | 合并转发并核清单 | 仅保留授权素材 |
| 查看待发包 | 核选择的 Bot 和附件 | 发送前能检查 |
| 取回收件状态 | 送达、失败或未知 | 摘要再走人工入库 |

## 小柚验证卡

在 Windows 用脱敏样本造两条聊天摘录、一张素材图和一份缺件清单，先留在本地。

- 模拟正常、附件遗漏和‘收到但回执未知’三种记录。核发送目标、已核文件数、是否已归档。
- 检查未知状态不会重复入库。记录人工核对用时与遗漏项。
