# 06 LivLiv Player：用固定角色资产做小柚的网页交互入口

核对日期：2026-11-21。原帖发布信息与当前源码分开记录。当前固定提交：`e3f6b640a338a22f8ac7e829821267a9a48b4a12`，package.json版本0.5.1。

这条适合补小柚的网页/直播交互入口：让同一份角色资产待机、变表情、播放回复音频并跟随声音动嘴，减少每轮都生成完整视频的需求。这是依据接口作出的应用判断，还没有小柚实测；播放器不生成对话或配音，也不制作角色模型。写实短视频、精确中文口型、任意身体表演及跨设备性能仍需各自验证。

## 能力与对小柚的价值

### 1. 先把“播放器”和“做角色”分开

Player读取.livliv包或model.json加贴图，把已有图层与绑定变成可动画角色。单张小柚参考图不能直接当完整LivLiv模型加载；需另做模型，或先用PNGTuber两张嘴部状态图/已有VRM验证。模型制作服务的条件、输出质量和授权另查，本轮未上传人物图。

依据：固定提交的README、API模型包说明与当前包名/版本。

### 2. 声音驱动口型，不自带回复和配音生成

createSpeech接收已有音频片段并排队播放，unlock需用户手势；stop用于停止。语音驱动源码依据声音强弱控制张嘴，并可用频谱线索影响圆/宽嘴形（取决于模型帧）。这不构成逐音素时间对齐保证。小柚仍需独立的对话和TTS环节。

依据：API的Lip sync节与src/runtime/voice.ts；未运行小柚音频测试。

### 3. 固定资产提供可控入口，一致性仍要看变形质量

待机、眨眼、表情和nod等动作可由参数/接口控制，适合表达等待、回答及回应。复用同一模型减少每次重新生成外貌的环节，是交互路线的潜在价值；大转头、嘴帧切换、头发或分层接缝仍可能暴露资产问题，不能直接承诺始终不变脸。

依据：API的params、expressions、actions说明；官方Nana笑脸切换已观察，动作轨迹未量测。

### 4. 当前能力超过面部，但有明确表现范围

当前0.5.1支持LivLiv模型，并通过适配器播放PNGTuber和VRM；新增4个全身示例，文档描述站立、摇摆、下蹲及说话时上身轻动。这些能力不等于全身人体动捕或任意跳舞，也不把2.5D模型变成可自由绕背的三维网格。它与Live2D Cubism独立，不读取moc3/cmo3。

依据：README和API Full-body/Body节；本轮未做VRM、全身动作或Cubism导入试验。

### 5. 轻量核心与整套加载成本要分别计算

原片约34KB，当前文档约30KB gzip均为核心口径，角色贴图、音频及附加驱动另计。摄像头跟踪还需MediaPipe，文档称首次约8MB；当前文档未宣称手机和应用内WebView经过测试。评价小柚时应记录完整首帧加载、音频开始和中断等待，而不是只比较核心包体。

依据：固定提交README/API；这些是项目文档数字，本轮未自行压缩或测速。

### 6. 代码开源与角色素材许可分别核对

代码标注Apache-2.0。精选角色许可1.1（2026-11-16）允许符合条款的个人商用并要求商用署名，公司/组织商用需另取得同意；Kujira/Kujira Q/Pen另有来源条款。Nana还是项目吉祥物，不能拿来当小柚或其他品牌形象。自有资产应按实际附带许可和权利来源判断。

依据：package.json、README与characters/LICENSE.md 1.1。这里记录原文边界，不替代具体用途的授权确认。

### 7. 先走已有音频的最小试验，再决定资产投入

首轮建议只用已授权角色加固定中文音频验证播放、口型和停止，不依赖摄像头。随后用小柚自有资产测风格接受度与大幅表情。面捕按需再加：文档说明相机图像本地处理，但默认仍下载外部模型/运行时并有MediaPipe统计请求；若需要无第三方连接，应单独核实完整部署方式。

依据：本项目的分阶段试验设计；API网络说明，未开启摄像头/麦克风或验证网络隔离。

## 从参考图到网页角色还差什么

03的参考母版可作为外貌依据；LivLiv Player的原生入口需要可播放的模型包，不能把人物设定表直接当成绑定好的角色。首轮可以先做PNGTuber两张状态图，用于判断网页有声角色是否值得投入。若希望连续转头、头发摆动与更自然表情，再制作专属LivLiv模型或已有VRM。各路线的制作质量及适用许可分别核对。

| 入口或材料 | 需要准备 | 首轮检查 |
| --- | --- | --- |
| PNGTuber占位路线 | 小柚闭嘴/张嘴两张授权图片；可加闭眼状态 | 适合先检验语音交互；画面以状态切换为主，不将其当成完整2.5D模型 |
| LivLiv专属路线 | .livliv包或model.json、图层贴图及绑定；记录生成/制作来源 | 检查脸、头发和嘴帧，大表情与有限转头是否破面；保留作者/许可信息 |
| 已有VRM路线 | 已授权VRM 0.x/1.0与VRM/three适配依赖 | 另测材质、模型表情、设备开销；不把它计入零依赖核心口径 |
| 固定中文回复音频 | 同一段包含闭口音、元音、停顿的自有/授权音频；保留原音轨 | 分别记录听到声音、嘴开始动、停顿闭口、停止后是否残留 |
| 交互状态与失败回退 | 待机/播放/停止/加载失败的操作设计；静态封面或图片回退 | 同一手势解锁音频；连续两段不重叠，停止后不再播放旧回复 |
| 设备与来源记录 | 包版本、资产文件大小、浏览器/设备、冷/热加载及适用许可 | 手机和应用内浏览器单独测；不以桌面示例代替所有环境 |

## 接入示意：已有音频如何让角色回应

以下仅是依据当前API的接入示意，未在小柚项目运行；省略页面元素、错误处理与资源准备：

```js
import { Player } from '@livliv-dev/player'
import { createSpeech } from '@livliv-dev/player/voice'

const player = new Player(canvas)
await player.load('/avatars/xiaoyou.livliv')
const speech = createSpeech(player)
startButton.onclick = () => speech.unlock()
replyButton.onclick = () => speech.say('/audio/reply-01.wav')
interruptButton.onclick = () => speech.stop()
```

`reply-01.wav`需由已有录音或独立TTS提供。这里没有文字生成、声音克隆或自动制模。表情ID应读取实际模型支持的列表，不能假定每个模型均有同一组表情。原视频中的旧包名不作为当前接入依据。

## 小柚的首轮试验

目标：验证固定资产能否让小柚完成一次可接受的中文音频回应；本轮只完成研究与官方基本交互检查，未执行该试验。

1. 先用音频播放按钮解锁声音，加载模型；记录打开页面至第一帧可见的时间，冷/热加载分别登记。
2. 播放第一段音频，核对张嘴、闭嘴、停顿；逐条记录可接受/不自然时点，不先假定音素精确。
3. 排队第二段回复，检查顺序与重叠；播放中按停止，记录从按下到听不见旧音频的时间及嘴部状态。
4. 调用模型实际存在的表情与nod，检查脸部接缝、转头范围和回到待机的表现。
5. 在目标手机与应用内浏览器重测；失败时检查静态图回退和错误提示。需要面捕时另立试验，不自动申请摄像头或麦克风。
6. 保留输入、版本、截图/录屏和失败点，评估这种风格是否适合小柚的交互场景，再决定是否投入专属资产。

验收：

- 区分模型加载、音频开始、嘴开始动和对话/TTS等待；不得把首帧时间当完整回答延迟。
- 同一模型在待机、说话、笑和点头时身份特征可辨，无明显新增断层、穿帮或嘴帧跳变。
- 中文发音与停顿可接受；严谨音素评分仍需另行标注和量测。
- 连续回复按顺序，无意外重叠；停止后无旧音频继续播放或嘴持续张开。
- 完整下载体积、冷/热加载、设备表现和视觉接受度都有原始记录；本轮数值留空。
- 使用条件与角色许可匹配，保留署名和元信息；小柚实作与个人消化分别记录。

[试验材料与记录模板](experiments/06-livliv-player/README.md)。当前所有小柚试验评分和耗时均留空，`reproduced`与个人`digested`不提升。
