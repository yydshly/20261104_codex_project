## 对小柚的核心价值

把稳定人物素材与包装分开：脸、口型和表演通过的底片保留，标题、字幕、装饰、位置和转场另改。这样能把“整段重做”变成“修改某一层的某个时间段”。

具体可用在：
- 片头或栏目开场：同一人物/插画素材，替换主题字和配色。
- 讲解包装：信息卡、关键词、章节和转场按语句事件安排。
- 系列短片：保留字体、层级与动作规则，比较不同文案版本。

这是一种可测试的生产分工，不是已证实的节省成本，也不解决底片中的变脸、口型或复杂表演。

## 可执行的层与时间规则

| 层 | 数据 | 检查 |
|---|---|---|
| 人物/源素材 | 文件、类型、哈希、身份基准、透明边缘 | 先验脸、口型、动作与发际，不让包装遮挡问题 |
| 文字 | 文案、字体、大小、起止与阅读顺序 | 长字不越界，字幕与脸可读 |
| 装饰 | 形状/贴图、重复数量、位置、透明度 | 服从信息主次，不因能复制就塞满画面 |
| 时间 | fps、事件秒数、整数帧、局部偏移 | 统一时间原点，检查首末帧与边界 |
| 音频 | 实际文件、裁切、偏移、拍点/词句 | 频谱不等于歌曲结构，实际听审 |
| 输出 | 预览、视频、音轨、时长和版本 | 浏览器动画不自动等于成片 |

候选帧方法可参考官方的[useCurrentFrame](https://www.remotion.dev/docs/use-current-frame)、[Sequence](https://www.remotion.dev/docs/sequence)、[interpolate](https://www.remotion.dev/docs/interpolate)。音频分析参考[visualizeAudio](https://www.remotion.dev/docs/visualize-audio)，其频谱输出与真正节拍/段落标记是不同概念，裁切与偏移还需统一。本轮没有安装或运行Remotion。

例如，**本项目示例**30fps、120 BPM时每拍15帧；10秒为300帧，编号0至299。这只是解释时间规则，不能当作原片fps或BPM。实际音乐有停顿、变速或不规则分句时，应按真实事件表安排，而非每拍强制切镜。

## 已经能操作的代码原理演示

[打开10秒结构预演](experiments/13-code-motion/timeline-demo.html)。

它是本项目独立编写的原生JS/SVG页面，无需安装额外包。使用文字和几何素材卡，不使用作者资产、原曲或小柚图片。可以：
1. 拖动或输入帧号。
2. 在引入、展开、收束之间定位。
3. 改标题和配色，观察时间位置保持。
4. 播放结构预演，再回到同一帧核对布局。

本轮验证结果：
- 0–89 / 90–209 / 210–299帧的章节边界通过。
- 越界帧限制到有效范围；F120对应示意第9拍。
- 界面F90显示3张素材卡、F210显示1张。
- F120修改标题/配色后，往返F210再回F120的布局状态相同。
- 播放从F120推进，最终到F299。

## 两条实施路线

**先用剪辑器验证。** 少量作品先用可用剪辑方式手工做出文案、主次与事件顺序，记下重复调整，确认规则值得复用再编码。

**把稳定包装写成模板。** 多次替换素材、文案、颜色或画幅时，将这些内容与布局分开，保留资产清单与时间规则；人物表演仍交给合适源素材。模板还要维护字体、长字、遮挡、随机性、素材加载和导出，不是写完就永远不用审片。
