# 030 · 从户型到可漫游空间：AI装修生成研究

从一张原木风客餐厅效果参考出发，完成一套可从入户门经过玄关、客厅走到阳台的Three.js原型，再研究如何将模型的理解、设计、编程和调试能力，结合标准资产、空间约束、渲染与验收，沉淀为可复用的装修空间生成流程。

**研究方向是“给户型，生成可修改、可走进去体验的3D装修方案”；当前已验证的是一套参考图驱动的房间，尚未证明不同户型自动适配。**

## 研究的问题

1. AI能否把装修效果目标转成可行走、可观察另一面的真实三维空间？
2. 能力来自模型本身，还是图形引擎、现成资产和实现规则的组合？
3. 沉淀的只是几套布局模板，还是能根据新户型选择家具并重新组织空间的流程？
4. 应当全部临时生成、先建庞大素材库，还是把最小资产库、参数化组件与模型设计结合？
5. 怎样通过实际行走、比例、支撑、碰撞、画面、性能及图形恢复验证结果？

## 本次实现与实际效果

- 以效果图合理补建门外、玄关、客餐厅与阳台，提供鼠标拖动、WASD、方向键、点击地面找路和常驻移动按钮；入户门可开合，碰撞与门扇动作使用同一几何依据，电视可开关。
- 导入有来源的沙发、电视、植物与PBR贴图，持续调整布料褶皱、窗帘、地毯、木质家具、花瓶、光照和电视反射，修复花盆悬空、比例与通行问题。
- 窗外制作七栋三维住宅、十棵主树和下层种植，补充不同楼高、退台、窗型、部分外开窗、阳台生活细节及轻微风动；视点移动具有各对象的空间视差。
- 排查WebGL Context Lost后的空白，增加暂停、恢复提示、环境光/后期/玻璃探针/阴影重建，以及保留位置、朝向、门、昼夜和未完成路线的重连机制。
- 取消恢复后长期降低清晰度的配置；恢复前后保留同样像素预算与2倍MSAA，初期呈现90帧时暂限30FPS，再回到60FPS。异步准备室内与庭院材质变体，减少首次转回室内的准备开销。

原型使用实体网格和真实相机移动，与原静态参考的家具细节和写实程度仍有差异。**当前“可编辑”指源码及场景参数可改，网页尚未提供家具拖拽、户型编辑或在线模型生成。** 庭院与邻楼为可观察的环境，没有制作下楼和进入邻楼的路线。

## 我们形成的理解

**模型是通用能力来源，稳定的专用流程需要资产、规则与工具共同支撑。** 这次没有训练新的图生3D模型，也没有改变模型权重；模型通过编程和迭代，组合Three.js、家具模型、贴图和程序生成几何完成原型。

素材库应包含模型、材质、真实尺寸、朝向与锚点、支撑面、碰撞范围、风格标签、复杂度、版本和来源许可。桌子要知道桌面高度，花瓶要知道底部和占地，电视要明确安装方式、屏幕材质和交互节点。当前已经使用了部分资产与约束，但尚未形成通用资产检索库。

固定布局模板记录某套摆法；可适配规则则描述支撑、朝向、门窗避让与通行关系，再结合户型和资产真实尺寸求解位置。我们希望验证后者，不能用已经做成一个房间直接证明它成立。

推荐的目标流程是：**户型与需求 → 统一场景数据 → AI设计与选款 → 程序规则校验 → 渲染与交互 → 验收与反馈。** 墙、地板、门窗和柜体可以参数化；核心家具从合格库中选择；缺失装饰按需制作并验收入库。把执行流程、代码工具、标准资产和验收标准一起沉淀为技能，便于下一轮沿用，不代表模型权重获得了新能力。

## 价值、意义与需要继续证明的部分

| 层次 | 当前可确认 | 希望形成的价值 | 如何验证 |
| --- | --- | --- | --- |
| 展示与空间体验 | 可以亲自移动视点、观察比例、视野与通路，并操作门与电视 | 帮助比较装修方案、发现空间问题 | 使用有真实尺寸的户型，观察真实使用者理解和修改行为 |
| 素材与实现复用 | 已有家具、材质、程序组件、操作逻辑与恢复代码 | 减少重复建模与实现工作 | 在新户型记录复用部分、人工调整点和实际耗时 |
| 布局生成 | 单套参考图驱动布局与部分约束已实现 | 从固定模板走向跨户型适配 | 三套门窗、尺度与通路不同的样本试跑 |
| 技能与验收 | 已有流程经验、问题修正和检查脚本 | 让后续生成任务更可重复、可追查 | 封装输入与工具约定，对照结果稳定性和人工修正量 |
| 产品与商业 | 有可操作的技术样板，尚无客户或收费验证 | 装修沟通、方案展示或其他空间规划产品 | 先验证真实需求、采用与投入产出，再判断是否继续产品化 |

没有测量生成省时比例、返工降低、客户理解改善、商业收入或跨户型成功率；不把这些目标写成已实现收益。

## 历史验证与当前边界

探索记录日期为2026-11-15，研究公开整理日期为2026-11-21。约17分钟的分段验收包含诊断、修改后的加载及主动恢复，完成8轮路线、41次昼夜切换和两次主动图形中断。第三轮曾短时降帧后正常到达；不能断言那次停顿与后来记录的资源准备耗时具有同一原因。

最终修正后的最后4轮均完成到达与整圈环视，没有新增超过250ms的操作阶段长帧；检查点59–60 FPS，纹理107、GPU几何缓存424、程序62保持稳定。图形恢复准备和首次加载仍可能等待，数值只对应当时本机视口，不能推断所有设备或无限时长均无掉帧。当前源码共有23项回归检查，公开包另做路径、来源、引导图一致性与部署检查。

当前没有实测户型解析、任意户型一键生成、家具拖拽编辑器、工程级尺寸与施工交付、手机实机或商业收益验证。公开站点没有接入在线模型API，也不收集或上传户型图。

## 后续验证顺序

1. 统一房间、门窗、资产、位置和材质的数据约定与资产标准。
2. 限定客餐厅和一种风格，把当前核心家具与组件整理为最小库和模板。
3. 选择三套尺度、门窗和通路不同的真实户型，分别记录生成耗时、人工修正和失败原因。
4. 按失败点补资产和规则，再比较误放、通行成功率、加载与运行表现，决定是否扩展。
