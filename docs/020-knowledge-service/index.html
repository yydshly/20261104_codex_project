DESIGN NOTES

一套流程，两种模型策略。

先实现可靠的客服闭环，再用真实对话验证双模型是否值得引入。

  1. 快慢是处理路径。同一个模型也可以采用不同推理配置；本演示用适配器展示两种策略。
  2. 事实由证据提供。政策来自带版本的文档，实时状态来自受控接口。
  3. 写操作由规则控制。退款要再次校验，并由用户明确确认；模型不能越过服务端权限。
  4. 交接必须有归属。人工接管后暂停机器人，带走完整处理上下文。
当前没有接入真实模型、登录、订单、支付或人工坐席。公开版会话与工单只在本页内存，刷新失效；服务端机制说明对应 Node 本地版。界面展示的是操作事件，不是模型思维链。
