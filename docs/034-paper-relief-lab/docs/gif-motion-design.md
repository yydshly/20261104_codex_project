# 《悯农》GIF 动作设计 · v1

状态更新：**第一景“一次锄作”GIF 已制作并接入，后三景仍为设计**。[观看第一景实际播放](https://yydshly.github.io/20261104_codex_project/034-paper-relief-lab/minnong.html?verse=1&play=1) · [制作与验收](minnong-noon-gif.md)。第一景实际采用 64 帧、50ms/帧、3.2 秒；以下 40 帧/80ms 等描述保留为最初设计值。

原设计阶段记录：本轮产物为[可查看的设计册](https://yydshly.github.io/20261104_codex_project/034-paper-relief-lab/gif-design.html)、本说明及[动作配置](../minnong/gif-motion-plan.json)。设计册展示现有静帧、计划重绘范围、运动路径和分镜文字，不能当作真实动作预览。原设计交付时的主页面为静态画稿与局部代码动效；目前第一景已替换为 GIF，后三景暂未替换。

## 要交付的体验

四句诗各有一幅纸墨小景。进入时画面安静，点击画内主体或动作按钮，人物完成一件事，停在变化后的画面；继续看下一句。情绪从劳作的吃力，经过汗滴与一餐，落到珍惜每一粒米。

参考原演示可见的有限彩墨、黑色剪影、纸白刻线、留白和局部回应，不复制原作构图，也不推断原演示的底层实现就是 GIF。保持现有四幅场景关系；第三、四景需要补画手部，才能建立手与米之间的因果关系。

**推荐结构：固定纸底 PNG ＋ 局部动作 GIF ＋ 结果静帧。** GIF 承载画好的真实动作；代码管理触发、暂停、切景与结果。GIF 格式本身不会改善人物造型，精致度来自关键姿势、接触关系、中间帧和统一的纸墨画法。

## 四景表演

| 诗句 | 动作与情绪 | 设计时长 | 播放与结果 |
| --- | --- | --- | --- |
| 锄禾日当午 | 稳脚、提肩、抬锄、落锄，肩背随后下沉；感到锄头的重量 | 3.2 秒 / 40 帧 | 点击演一次，锄刃留土，脚边多一小块新土 |
| 汗滴禾下土 | 额角聚汗，脱离、加速下落，接触禾根旁的干土 | 2.4 秒 / 30 帧 | 一次汗落，湿痕留下，禾叶轻应后停止 |
| 谁知盘中餐 | 右手入画持筷，夹起一粒米，稍停，再轻放布巾上 | 3.2 秒 / 40 帧 | 手退出，筷子回桌边，一粒米留在布上 |
| 粒粒皆辛苦 | 拈米手夹合、带米移动、放入接米的掌心、退出 | 每粒 1.6 秒 / 20 帧，共 5 段 | 每次收下一粒；散米减少、掌中米增加，五粒收齐后停住 |

每帧暂按 80ms（12.5fps）设计，用手绘纸版画的节奏表达短动作；这是制作起点，不是已经验证的最佳帧率。先审第一景的落锄段，若动作不连贯，补绘过渡帧、调整时长。动作接触清楚和造型稳定优先于机械补帧。所有时长、帧数和范围均为计划值，实际成片须另行记录。

### 01 · 锄作：让一锄有重量

- 0.00–0.64s：支撑脚不挪，肩先提起，双手带动锄柄。
- 0.64–1.28s：抬锄到可辨认的高度，顶点留约两帧停顿。
- 1.28–1.84s：重心带动肩、肘与整把锄落下；锄刃接触后两帧内才出现少量土屑。
- 1.84–3.20s：锄刃留土，肩背稍沉，袖褶最后落定，末段留静止余味。

必须重画上半身、双手与锄头，不能仅旋转整个人物贴图。两手握在同一根刚性锄柄上，柄长不变；脚不滑地。避免大幅扭腰、卡通弹跳、满屏尘烟。树、太阳、田埂和幼禾保持固定。

### 02 · 汗落：让视线落到禾根

- 0.00–0.48s：帽檐下额角聚出汗珠，先黏附皮肤，头轻轻低下。
- 0.48–1.04s：汗从额角脱离，向下加速，形状只做细微拉长。
- 1.04–1.44s：汗珠碰土，湿痕沿纸纤维方向微微润开。
- 1.44–2.40s：相邻一片禾叶轻动后停住，湿痕留下。

原图帽檐内侧需补汗的来源；不能让汗从空白处凭空出现。手仍持锄，身体轮廓稳定。没有闪光、弹跳或禾苗瞬间生长。

### 03 · 一餐：给米粒一个真正的搬运者

- 0.00–0.72s：补画的右手入画，拿稳桌边筷子。
- 0.72–1.36s：筷尖伸向饭碗，合住一粒米。
- 1.36–2.16s：提过碗沿，停约三帧，目光集中到米粒。
- 2.16–3.20s：移至布巾，松米、放回筷子、收手；结果定格。

需制作去除原有筷子的干净底图，桌上不能同时残留一双筷子。手的红袖与前两景呼应，保持平面黑墨造型和少量纸白刻线。筷子握持与米粒接触全程可信。饭碗、桌沿和布巾固定；首版不另加蒸汽循环，先让主动作成立。

### 04 · 珍米：每次认真拈起一粒

- 0.00–0.40s：第二只手从上方进入，拇指、食指靠近并夹合。
- 0.40–0.80s：指尖夹着米，手腕沿短弧移向掌心。
- 0.80–1.12s：接米掌指轻应，拈米手松开，米留在掌纹间。
- 1.12–1.60s：拈米手退出，静置到片段结束。

首版采用**固定顺序收下一粒**：按钮“拈起下一粒”和下一粒米的热点触发同一段。当前主页面允许任意点米，这是后续 GIF 版拟调整的交互，并未在本轮悄悄改掉。若保留任意顺序，五粒米就会产生最多 32 个集合状态及 80 条单粒收取转移，不能复用五段有累计结果的整块 GIF；需要单独的手部动作资产和动态米层，作为后续扩展。

制作 `state-0.png` 到 `state-5.png` 六个完整结果状态，以及 `action-0-1.gif` 至 `action-4-5.gif` 五段动作。每段必须继承之前已收的米。粒数仅在片段完整结束时提交；切景或暂停不算完成，不会重播后重复增加。最后五粒都在掌中，不加入庆祝、光效或提示弹窗。

## 素材契约与纸墨连续性

以下为四景的素材约定；第一景实际文件与差异见 [制作记录](minnong-noon-gif.md)，后三景仍待制作：

```text
assets/minnong-gif/{sceneId}/
  base.png                  # 清理掉可动主体的固定底图
  state-0.png               # 全幅起始画面；与第一帧一致
  state-1.png               # 全幅结束画面；与最后一帧一致
  action-0-1.gif            # 局部裁片，单次动作
  mask.png                  # 固定软蒙版，静止纸面上收边
  masters/frame-000.png      # 原始全彩逐帧稿；无损保留
  manifest.json             # 坐标、时长、状态、素材哈希与来源
```

第四景增加状态 2–5 和对应五段 GIF。全套共 **8 段动作 GIF、12 张起止／累计状态图、4 张清理底图、4 张蒙版**；原始帧另存。分享版全幅 GIF 由同一帧序列另外合成，不能把局部裁片直接当成完整成品。

坐标采用现有画稿 1536×1024。设计册的框是动作范围的初稿，不是最终裁片：先确定最大抬手、抬锄范围，再留出边缘。补画后重新核定；第三景必须容纳新手从画外进入，第二景须容纳从额角到土面的完整路径。裁片、蒙版、PNG 状态图使用同一套对齐坐标。

保留高质量全彩原始帧，再制作 GIF。每段使用稳定的调色板与相同底纸，静态纸像素不逐帧生成。GIF 的颜色表与透明索引有格式限制，不能指望直接保留柔和的半透明压印边缘。[GIF89a 规范](https://www.w3.org/Graphics/GIF/spec-gif89a.txt)

因此优先使用**带底纸的非透明裁片**，通过固定 PNG 软蒙版叠到原底图；蒙版收边放在静止区域。先完成第一景 GIF 量化试样，检查裁片接缝、红衣色阶、纸白刻线与压印阴影，再确定调色板、抖动和边缘过渡。蒙版不能补救整片纸纹与原图完全不匹配的问题；一旦出现纸色跳变，需返修底图匹配或编码方式。

起止状态 PNG 应由**最终 GIF 解码后的首／末帧，按同一蒙版合成到底图**得到，不能直接换回量化前的母版局部，否则播放开始与结束会发生颜色跳变。第四景后一段的首帧须与前一段末帧使用相同的累计米粒、纸面和调色板。

网页计划输出两档：1024 宽对应全幅坐标的桌面裁片、768 宽对应全幅坐标的移动裁片，保持原始长宽比。1536 宽 PNG 帧保留作为母版。文件大小先以每段 1–4MB 为试样预算，不作为已实现的指标；纸纹压缩不足时，优先裁小动作区和优化静帧停留编码，不能先牺牲手与米的轮廓。

## 播放状态与实现边界

```text
ready(state-n) → loading → playing(action-n-to-n+1)
                              ↕ paused（同一帧）
                           完成末帧停留
                              ↓
                       settled(state-n+1)

loading / playing 出错 → 保留 state-n，允许重试，不提交完成
```

网页不只放一个自动循环的 `<img>`。设计采用 GIF 解码后在 Canvas 中合成，才能保存当前帧、累计时钟、暂停与精确重播。可选用 `gifuct-js`，但本轮未安装依赖；该解码器提供帧延迟、位置、像素补丁与 disposal 信息，合成器仍需自行正确处理。[gifuct-js 官方说明](https://github.com/matt-way/gifuct-js)

- 每帧按实际 `delay` 显示，不能假设输入总是恒定帧率。处理帧矩形偏移、透明索引与 disposal 0/1/2/3，防止残影和擦除错位。GIF 延迟单位与帧处置规则以[GIF89a 规范](https://www.w3.org/Graphics/GIF/spec-gif89a.txt)为准。
- 暂停冻结帧与时钟；切景仅暂停当前景，回来继续该帧。标签页隐藏也暂停，回来不补跑离开期间的时间。
- 播放时忽略重复点击，不排队。动作按钮显示“正在锄作／汗正落下／正在取米／正在收米”。完成后首三景按钮改“再看一次”，点击从该景起始状态重演；第四景前四次为“拈起下一粒”，完成后“重新收米”复位当前景。
- “重看此景”只复位当前景。若在播放中重看，取消当前播放 token，迟到的加载／结束回调不得再次提交旧状态。
- 尊重减少动态设置：进入显示起始静帧，用户主动点击后直接展示对应结果静帧。第四景每次只提交一粒；不会自动完成所有故事。
- 只解码当前片段；下一段只预取压缩文件，不能把 8 段高清 RGBA 帧全部常驻内存。释放上一个片段的帧缓冲与位图。以当前裁片和桌面档估算，最大单段完整 RGBA 帧约 47MB，另有合成与解码开销；移动端另测峰值内存，不能仅按 GIF 文件大小判断。
- 加载失败仍保留清晰静帧与诗句，显示简短重试入口；不让人物消失，也不假装动作已完成。
- GIF 版继续使用四个诗句入口、画内热点、按钮与键盘。热点随画幅等比映射；小米粒提供大于可见轮廓的点击范围，按钮始终提供等价操作。

## 第一段制作指令草案

以下是**未执行的制作方向**，不是已提交给模型的历史提示词。制作时应提供实际画稿作为完整编辑目标，并提供本地原演示截图仅作风格参考；记录准确提交文本、工具、输入与原件。人物一致性差或接触错误的帧需定向返修，不能依赖转换格式解决。

> 为《悯农》第一句制作固定机位、单次锄作的逐帧动作。使用现有第一景画稿作为构图、人物、器物、配色与纸墨材质的完整编辑目标，保持左侧细树、高处赭黄太阳、两道田埂、幼禾和大面积留白。情绪是炎热午间劳作的一次吃力呼吸，结尾安静。人物维持黑墨剪影、朱红短衣、赭黄斗笠、细纸白刻线；不要转成写实人物、三维塑料、浓密排线或整张纸在抖动。动作顺序：双脚站稳，肩先提起，两手握住同一根刚性锄柄，抬锄并稍停，身体带动锄刃落土，接触后才有少量土屑，肩背缓缓下沉，锄刃留土。支撑脚不滑动、手不穿柄、柄长不变、帽子和衣褶随身体自然响应。镜头、纸面、树和太阳全程固定，不推拉，不加文字、粒子、光效与音效。先制作起势、最高点、触土、收势四张关键姿势，核对接触后补中间帧，保留全彩无损原始帧。目标 3.2 秒，帧数与落锄节奏以审片结果调整，末段留停顿。

## 制作与验收顺序

1. 第一景关键姿势：并排检查四张，双手、锄柄、肩背和支撑脚成立后补中间帧。
2. 第一景 GIF 试样：逐帧看片，再按正常速度播放。与源静帧并排看纸墨质感，检查裁片接缝和首尾切换。用户对表演和质感的判断是审美验收，程序测试不能代替。
3. 第一景接入播放器：验证点击一次、暂停、返回继续、重看、失败重试及减少动态设置，再扩展汗落、持筷与五段拈米。
4. 最后才输出全四景播放录像和分享 GIF，实际报告时长、帧数、大小及已知偏差。不得用静态图加漂浮米粒的录屏冒充完成的手部动作。

| 验收项 | 可观察的依据 |
| --- | --- |
| 动作真实发生 | 人的肩肘、持筷手、拈米手确实改变姿势；没有只有米和土在动 |
| 接触与守恒 | 手始终握住道具；先接触后响应；第四景总米数始终为五 |
| 风格连续 | 同一个人、同一把锄、同一张纸；黑色轮廓清楚，纸白刻线不跳动 |
| 画面固定 | 动作范围外固定像素一致；没有整纸抖动、呼吸缩放或裁片色块 |
| 播放可信 | 首帧与起始状态对齐，末帧与结果图对齐；暂停、切景、重复输入与故障不跳状态 |
| 分享完整 | 全幅 GIF 含完整场景；离开网页能正常打开，且不会无休止播放一件叙事动作 |

## 可以沉淀的能力

沉淀为“有前后状态的插画动作”，而不是每次手写一个动效页面。配置包含诗句／文案、静帧、动作区域、触发热点、GIF 片段、完成状态和替代静帧；播放器复用，画稿与动作仍须分别制作和审美验收。

适用于诗词／节气小景、产品介绍中的单步操作、手作与器物过程、博物馆或非遗知识卡、关系故事中的递物回应。先复用点击—动作—结果这一结构。自由拖拽、任意物体组合和长连续表演需要另一套资产与逻辑，不能仅靠固定 GIF 承诺支持。
