# 从一件作品到产品与可复用能力

实施进展：首版本地制作台已完成现有故事配置化、单幕编辑、图稿替换、预览、本地草稿、网页包/封面/长图导出，并加入见全作为第二个案例。使用见 [studio-guide.md](studio-guide.md)，核验见 [制作台交付记录](../reports/studio/verification.md)。下文保留原产品规划，其 SDK、付费与更多方向仍为后续方案。

日期：2026-11-15。依据本项目实际代码与工作区相关项目说明提出的产品设计方案。优先级是内部判断，没有做市场规模、竞品价格或付费需求验证；下面的产品、接口和指标都是后续方案，不表示已经实现。

## 核心定位

沉淀“把一个故事转成可阅读、可局部修改、可导出的视觉介绍”的能力。纸墨是首个视觉主题，《留半篮秋天》是首个关系故事样本。首版继续使用静态画面。

需要形成三个能单独复用的结果：

1. **创作方法**：简报、人物目的、事件变化、分镜、画面检查与定向返修。
2. **生产工具**：内容格式、人物与场景资产、渲染和导出、版本管理。
3. **用户产品**：创作者编辑故事，观看者阅读故事；两种界面的任务不同。

## 当前能力与缺口

| 能力 | 现有证据 | 可先沉淀的内容 | 尚缺什么 |
| --- | --- | --- | --- |
| 故事到分镜 | `docs/creek-story.md`；用户接受重逢故事 | 人物目的、物件作用、四幕变化与检查问题 | 换题材后的有效性；当前样本不是通用叙事公式 |
| 角色与姿态 | `story-art.js` 的父亲、女儿、手部与接触绘制 | 当前人物资产、身份配色、已有姿态及接触锚点 | 姿态普适性、任意人物替换；当前大量坐标与衣物写死 |
| 场景与镜头 | 溪桥背景、前三幕全景、结尾固定近景 | 环境图层、近远关系、镜头数据 | 标准场景文件与适配规则；当前依赖继承与条件分支 |
| 纸墨风格 | `woodcut.js`、`creek-art.js`、`story-art.js` | 颜色角色、线面、纸面着色、合成/线面对照 | 独立模块 API；现有实现使用全局类替换，尚非 SDK |
| 稳定输出 | `reports/stills/render.mjs`、八张 PNG、静态检查 | 同一份画面输出合成与线面图、文件记录 | 全故事内容导出、长图排版、发布包与字体资产清单 |
| 阅读体验 | `story.html`；桌面与模拟手机排版检查 | 四幕阅读页、原图查看与辅助描述 | 配置驱动的阅读器；当前正文、路径和布局是手写 HTML |
| 创作与修改记录 | 各轮归档、制作说明、文件 SHA-256 | “哪一幕、为何改、改了什么、原件在哪”的记录格式 | 可查询的资产版本与用户反馈结构；继续制作不代表用户认可 |

因此，当前适合称为有源文件和核验记录的原创样本。封装成可调用能力，应以第二个不同题材能复用流程和基础模块为验收。

## 推荐先做的产品：故事介绍页制作台

第一批用户先是我们自己。用现有项目的介绍任务验证生产流程，随后再判断是否发展为创作者工具或对外制作服务。

**输入**：给谁看、希望他理解什么、人物或使用者遇到的问题、事情怎样改变、可以使用的文字与素材。

**编辑过程**：梗概 → 分幕 → 选定场景与视觉主题 → 正式静帧 → 局部修改 → 预览与导出。支持变长的幕数；当前先给四幕作为起步模板，不强迫所有故事使用四幕或“收集六次”。

**输出**：可阅读的网页、含全部文字与素材的本地发布包、封面、可分享长图。静帧与短片以后可以消费同一份分镜，但本轮不制作动画或视频。

**首版边界**：一个纸墨主题、人工编辑文字、有限场景和人物资产、图片或已有图稿导入、单幕替换、预览与本地导出。人物与分镜允许人工创作和审核。先不承诺任意文字都能自动生成高质量人物，也不扩展账号、协作、订阅和素材商城。

观看者进入成品应直接读故事；材质调节、法线、版本记录位于制作端或研究入口。创作者修改第三幕时，前两幕不能被无故重做。

## 可沉淀的方向和场景

| 顺序 | 方向与具体任务 | 交付结果 | 验证价值的方法 |
| --- | --- | --- | --- |
| 先在内部用 | **产品介绍与导览**：把“用户遇到问题—采取行动—看到变化—下一步”讲清楚 | 故事介绍页、发布长图；入口连接真实产品功能 | 读者能否说出产品解决什么问题，并进入正确的功能；记录误解与退出位置 |
| 第二个内容试验 | **纪念与关系表达**：感谢、重逢、告别、生日、一段家庭小事 | 可送人的故事卡、短画册或本地保存包 | 创作者能否说出这件事“像我们”，并愿意实际送出、保存或再做一份 |
| 有真实委托后试 | **地方文化与展览**：一座桥的故事、一件器物的流传、节气中的一件事 | 图文微展览、展品介绍页、导览卡 | 读者能否记住核心事实；事实、来源和创作部分能否清楚区分 |
| 同一叙事能力的迁移 | **教育与机制解释**：一个误解怎样发生、一个过程怎样改变结果 | 分步故事、教师讲解卡、入门教程 | 阅读后能否解释因果并完成相关任务；不能只评“好看” |
| 后续受控试验 | **个人回顾与成长记录**：从手工选出的几条记录讲一段变化 | 周月回顾、阶段纪念页 | 是否忠于材料与时间；缺失信息保持空缺，不用虚构细节补齐 |
| 多题材复用后再做 | **组件与 SDK**：给其他项目接入统一的故事阅读器、主题和导出 | 可嵌入组件与内容格式 | 第二个项目是否无需复制人物和页面源码；主题切换是否保留故事内容与可读性 |

这些场景的需求与商业回报均待验证。文化与教育任务增加事实审核，关系故事强调本人认可，个人记录强调选材与时间口径；不能用同一套验收覆盖所有方向。

## 对工作区已有项目的价值

以下仅根据本轮读取的各项目 README 作映射，没有接入或修改这些项目。

- **见全 / 认知电梯**：已有“AI 为什么会答错”的产品导览，以及 `tour.json` 驱动的内容和时间轴。适合作为第一个业务使用者：尝试把一次疑惑、核对、寻找证据和自行判断，变成一段可进入真实功能的静态故事介绍。参考其配置与画面分离方法，不另造一份相同的时间轴系统。
- **AI 短片工作室**：已有剧本、角色、分镜、素材、配音、字幕与导出的生产流程。这里可以补“静态视觉叙事与图稿验收”分支，未来再把接受的分镜交给短片流程；当前不提交生成任务或制作动作。
- **青白造境**：可作为以后第二个材质主题的候选。先验证同一故事换材质仍能讲清楚，不把瓷质图形的直接换色称为风格迁移完成。
- **留一会儿**：已有纯看图、收藏与图像对照。可以比较独立氛围图与带事件关系的短故事，检验文字和事件是否改善观看体验，不预先声称有情绪或留存收益。

日常记录方向先使用手工选择的示例或脱敏输入。这里不读取或接入 日常复盘工具 的库、缓存及程序。

## 工程化的第一步：用内容配置替代逐故事改程序

建议一个故事目录持有 `story.json`、人物设定、场景与图稿、每幕文件、文字和检查记录。配置表达“讲什么”和“用什么资产”，不要把身体坐标混进旁白。图稿来源可以是程序、手工绘制或导入图片，由各自适配器输出统一素材与来源信息。

概念接口（尚未实现）：

```json
{
  "id": "half-basket-of-autumn",
  "title": "留半篮秋天",
  "audience": "阅读一个重逢故事的人",
  "theme": "paper-ink",
  "characters": ["father", "daughter"],
  "scenes": ["creek-bridge"],
  "beats": [
    {
      "id": "recognition",
      "purpose": "让父亲和女儿用熟悉的动作相认",
      "narration": "桥上响起脚步，又停住了。",
      "dialogue": "还给我留着地方吗？",
      "scene": "creek-bridge",
      "cast": ["father", "daughter"],
      "visual": "stills/03.png",
      "alt": "女儿举起秋叶，父亲抬头举手回应。",
      "camera": "wide",
      "review": "pending"
    }
  ],
  "outputs": ["web", "cover", "long-image"]
}
```

这里的 `purpose` 是幕后验收依据，不强制展示给读者；`review` 需保留实际反馈，不自动把渲染成功记成艺术认可。纸墨参数属于主题，人物与姿态属于资产，阅读器和导出消费同一份内容。先完成内部工具，再根据实际复用压力决定模块和 SDK 的边界。

## 下一轮四个完成条件

1. **配置驱动。** 将当前接受的故事内容搬入配置，阅读页不再手改每幕 HTML；图稿与角色资产有来源及版本。
2. **完成交付。** 从同一份内容导出网页包、封面和长图；单幕改字或换图不会改变其他幕；导出内容可直接阅读和交给别人。
3. **迁移验证。** 做一个明显不同的题材，优先选择我们自己的产品介绍。记录哪些模块直接复用，哪些仍需重新制作、人工花在哪一步。
4. **使用验证。** 预先约定读者应理解什么、完成什么行动，再做小样本试用。记录读懂情况、修改次数、单件制作耗时、真实使用与再次需求。

只有完成以上迁移和使用验证，才讨论把它扩大为外部制作服务、模板产品或 SDK。小样本中的理解正确率与真实送出行为提供方向，不把它们直接解释成付费市场或长期留存证明。

## 商业化的可能路径

初期可用固定范围的单件制作服务学习需求与返工成本；常见需求重复出现后，提炼为有限模板和编辑器；重复使用明确后，再评估自助工具的收费。组件或 SDK 面向已有网站的团队，应以能独立接入和维护为前提。

不预设价格与收入。先计入选题、文字、图稿返修、沟通和导出的人力，验证用户为哪一部分交付付出时间或费用。当前最优先的沉淀是内容格式、生产闭环和第二个真实应用，而非增加更多风格样张。
