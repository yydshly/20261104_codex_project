# 故事介绍页制作台 · 首版

本机入口：[制作台](https://yydshly.github.io/20261104_codex_project/034-paper-relief-lab/studio.html)。在项目目录运行 `npm.cmd start`，使用终端给出的地址；端口占用时可能改用其他端口。制作台与配置阅读页需要本机服务器，导出的单文件网页不需要。

《留半篮秋天》现另有 [动作舞台](https://yydshly.github.io/20261104_codex_project/034-paper-relief-lab/stage.html)，见 [舞台说明](motion-stage.md)。默认秋天阅读链接会进入舞台；加 `&mode=static` 可看四幅原静帧。动作舞台读取内置源配置与专用角色绘制代码，不读取浏览器草稿。制作台修改内容后的预览及所有导出仍为静态，不能将替换的图片自动变成角色动作。

## 使用

1. 顶部选择《留半篮秋天》或《AI 为什么会答错？》。左栏选一幕，中栏改标题、正文、对话、短句、图片描述及可选入口，右栏即时预览。
2. “替换图稿”只修改当前幕。支持 PNG、JPEG、WebP，单文件不超过 10 MB，适配后最长边不超过 2400 像素，图片以 PNG 放入草稿与配置。磁盘上的原图不被覆盖。
3. 修改后自动保存，也可主动“保存草稿”。本地草稿与初始示例配置分开，两份案例各自保存。每次打开默认进入第一个案例，其他案例的已保存草稿可从选择器恢复。
4. 标题和网址尚未写完时允许保存并继续编辑，阅读预览使用临时标题并暂不显示无效入口；导出前必须完成必填标题与有效链接。
5. 左栏“整篇故事设置”可改故事标题、介绍、读者、结尾、主题与封面主图。分幕可新增、排序和删除，范围为 1–12 幕。“恢复此幕”回到这幕载入时的来源内容。
6. “整篇查看”打开完整阅读预览，手机按钮以较窄内容宽度查看效果。制作台中的预览和导出均为静态。

草稿保存在当前浏览器、当前站点地址的 IndexedDB。它不修改源 JSON；更换浏览器或地址、清除站点数据会影响草稿可见性。需要独立留存时使用“导出配置”或网页包。保存反馈以事务完成为准，相关语义见 [MDN IndexedDB 说明](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)。

## 三类成品与配置

| 导出 | 文件与内容 | 怎样使用 |
| --- | --- | --- |
| 网页包 | ZIP 内有 `index.html`、`story.json` 和 `README.txt` | 解压后打开 HTML。图片内嵌，阅读无需网络、脚本或额外字体；外部产品入口需要对应网站可访问 |
| 单文件网页 | 网页包生成结果中另有 HTML 保存入口 | 直接打开或作为静态页面交付 |
| 封面 | 1600 × 900 PNG，使用所选分幕的主图 | 封面标题适应长度，较长开场介绍会精简为三行；正文仍完整保留在网页和长图 |
| 长图 | 1200 像素宽，按实际图稿比例和全文自动排版 | 包含开场、所有分幕、对话、图注、入口地址与结尾。超过画布安全范围会提示缩短内容，网页包仍可导出 |
| 配置 | 内嵌图稿的 JSON | 可导入制作台成为独立副本，继续修改；不覆盖已有项目 |

导出会提供可见预览和持久保存链接，同时尝试浏览器下载。自动下载是否落到系统下载目录，取决于浏览器设置；本轮核验的是按钮实际生成的字节和文件的独立可用性。

## 内容格式与模块

- `stories/catalog.json`：内置案例目录。
- `stories/autumn.json`、`stories/jianquan.json`：两个 version 1 故事，统一使用 `beats`；每幕保存文字、叙事目的、图稿、图片描述和可选入口。
- `studio/story-core.js`：同一份内容校验与阅读排版，编辑预览、独立阅读页、离线网页都使用它。
- `studio/exports.js`：图稿适配、封面、长图与 ZIP 输出。不会重新生成故事或改变其他幕。
- `studio/studio.js`：编辑、选择、局部恢复、草稿保存与导入。
- `studio/reader.js`：按故事名载入配置；已知的溪桥动作适配器进入舞台，`mode=static` 强制使用共用静态阅读器。

新增内置案例只需准备配置、图稿并加入目录，不需要再写一份编辑器或阅读页。导入配置要求内嵌图稿；可先在现有案例中修改，再导出为可移交的配置。

用户文字按文本转义，功能入口限制为 HTTP/HTTPS，上传图稿先解码并适配成 PNG。未实现多人协作、服务端账户、自动图像生成或视频生产。

## 第二个案例：见全

采用本地 `society-atlas/dist/roam-data.js` 与 `capability-elevator/public/tour.json` 已有内容：发现闭馆时间差异 → 理解生成机制 → 核对通知版本与适用条件 → 形成有边界的判断并继续探索。

星桥图书馆、通知和助手回答均为原项目的教学虚构。旧通知为每日 18:00；现行通知的周一至周五为 18:00，普通周日为 16:00。本轮没有调用真实模型，也没有将虚构安排当作真实馆规。四幅图为原创教学图解，未伪装成产品截图。

两份案例共用同一份数据契约、编辑器、预览、草稿与导出代码。不同的是内容、图稿、视觉主题和功能入口。见全的本地入口使用 `127.0.0.1:4173`，需原产品服务在该地址运行；修改入口网址即可适配其他部署地址。本轮没有改动见全源码。

这验证了两类内容的工具复用，尚未证明所有题材的图稿可以自动制作，或读者因此更容易理解产品。详细证据见 [制作台核验](../reports/studio/verification.md)。
