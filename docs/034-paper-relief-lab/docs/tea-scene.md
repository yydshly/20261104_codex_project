# 雨后茶棚 · 炉边煮水

本机入口：[tea.html](https://yydshly.github.io/20261104_codex_project/034-paper-relief-lab/tea.html)。沿用项目的 `npm.cmd start`，默认端口为 5218。研究首页增加了新作入口，溪桥、制作台与原静态故事保持独立。

## 意图与画面

故事是雨停以后，茶棚准备第一壶茶。观看者添一块干柴，等火接稳、壶中水变热，再看到壶嘴细汽。以一件可以参与的小事表达安静开张的节奏。

参考是 Ann Nguyen 原作录屏中可见的有限彩墨、明确线面、大幅纸面留白与局部因果反馈；没有操作作者应用，也未验证其源码。本景的棚、器物和构图独立绘制。沿用本项目纸墨表面，不取样原作素材；没有使用图像或视频生成服务。

识别中心为深墨绿铁壶与暖赭陶炉。铁壶分别绘制提梁、藤缠的弧度与绑线、连接铆点、壶盖口沿、壶嘴空腔、铸铁短刻痕与阴影面；炉口有内外厚度、铁支脚、炉膛和下方进气缝。木柴绘制木皮、切面和年轮，背景用轻竹棚、空茶杯、湿石板、远坡与蕨叶交代雨后环境。

第一次实际审看后，抬高棚沿，让它与提梁分离；调整地面与桌脚的遮挡顺序；把初始大火收成余火；增强水汽的可辨识度。首次画面及源码保留在 `reports/tea/revisions/`。

## 参与与状态

| 阶段 | 可见变化与文字 |
| --- | --- |
| 余火 | 三块干柴在左下角，炉膛有少量红炭，壶嘴没有水汽 |
| 添柴 | 一块柴沿前景进入炉口，柴堆剩两块；火焰随后渐长 |
| 火稳 | 约 3.8 秒后火势稳定，壶仍未出汽 |
| 将沸 | 水继续变热，细汽稍后才出现；说明文字随实际出汽时机变化 |
| 水开 | 添柴后约 11 秒进入完成状态，壶盖小幅轻动，火与细汽继续低幅变化 |

点击干柴与按钮进入同一动作，重复点击不会再加一块或重启动作。暂停保持时间和全部动态；重新煮水恢复原来的三块柴、余火与无汽状态。切出页面会暂停。开启减少动态效果时，添柴直接显示完整结果；运行中切换同样会转为稳定画面。

这里用“热度”这一抽象状态安排观察节奏，没有显示温度，也不把约 11 秒描述成现实煮水时长或热力学模拟。当前是一幅景、一次添柴，不扩展注茶、人物表演或多场景编辑。

## 实现与可复用部分

- `tea/scene.js`：纯时间状态 `Model/sample`、器物与空间绘制、静态缓存、局部纸墨着色。只继承 `renderer.js` 与 `woodcut.js` 的绘图和材质基础，未复制溪桥人物时间线。
- `tea/app.js`：同一份状态驱动画面、文字与操作；实际帧时间、暂停、命中、键盘按钮、减少动态与后台停留。
- `tea/tea.css`、`tea.html`：主画面、简短故事与三项控制；桌面和窄屏使用同一幅构图。

静态画面缓存为三块柴和两块柴两个版本。每帧只重新绘制炉膛、壶盖、水汽，以及短暂的入炉柴木和檐角滴水区域。纸纹始终固定在全局纸坐标，人物与器物之外的背景不会随状态重新随机生成。水汽是从壶嘴出发的低透明度曲线带，不是覆盖整幅画面的雾层。

当前迁移验证的是：同一材质与绘图基础，可以从人物关系故事迁移到器物和环境的交互小景。新器物造型、遮挡、交互和节奏仍需单独制作，不表示已有通用场景 SDK 或任意图片自动动画能力。

## 核验与交付

可复查命令：

```powershell
npm.cmd run check
npm.cmd test
node reports/tea/inspect.mjs
node reports/tea/check.mjs
python reports/tea/visual-check.py
node reports/tea/record.mjs
python reports/tea/encode-preview.py
```

纯模型检查了热度连续累积、重复输入、暂停和重置。浏览器从点击干柴开始实际等待火稳、将沸、出汽和水开，验证文字时机、重复输入、暂停像素保持、重置、Enter 键、运行中切换减少动态与 390 像素画布命中。完整结果在 [checks.json](../reports/tea/checks.json)。运行中切换减少动态的检查发现了媒体查询值同步问题，改为按变更事件维护状态后重新核验。

三块固定区域跨余火、火稳、细汽与水开四帧逐像素相同；炉口暖色区域与水汽区域的变化单独检查，见 [paper-check.json](../reports/tea/paper-check.json)。这验证背景稳定且主要反馈确实出现在炉膛、壶嘴，不能代替对艺术完成度的判断。

[tea-preview.mp4](../reports/tea/tea-preview.mp4) 来自页面 Canvas 的实际一次完整交互录制，随后转换为 H.264。1000 × 630、24 fps、无声；完整解码、核对时长与帧数并抽取 16 个时间点，见 [video-check.json](../reports/tea/video-check.json)。检查方式为实际页面运行、关键帧目视审看和完整解码，不是逐帧人工审片。
