# 赤霄浏览器验收

本记录只对应赤霄 V3；旧版骑士、水晶试炼和旧 Windows 程序的结果不计入本次。

## 验证方式

在本地构建目录启动 HTTP 预览，使用实际浏览器界面操作近景、演武、技能和结算。只读取页面 DOM 与浏览器日志；没有通过修改游戏状态制造胜利。

验收区分三件事：纯规则测试核对命中和状态；GLB 检查核对骨架、蒙皮、动作与挂点；浏览器截图和手动操作核对实际构图、动作和反馈。

## 最终版本结果（2026-11-12）

最终 GLB SHA-256：`9fa5b9cbbf011a4967b039f8b4a7d52330c8aa2ad7bdf09aa3808d5406ef077c`。浏览器从最终构建首页载入，点击「看技能连段」后，以同一玩法规则击败三名守卫：6.5 秒、10 次有效命中、剩余生命 240；这一轮护盾承伤为 0，不能据此单独证明承伤效果。浏览器警告与错误日志均为空。

- [最终英雄首屏](warlord-hero.png)：成年重甲、双手战戟、完整戟刃构图。
- [实际落地命中](warlord-impact.png)：落地同一刻出现 76 点真实伤害，三名守卫离地，角色压身，地面冲击反馈可见。
- [最终通关](warlord-victory.png)：真实页面结算，未从脚本直接改写胜负状态。
- [390 像素窄屏](warlord-mobile.png)：英雄与文字分开，按钮可见，没有横向溢出；检查完成后已恢复桌面视口。

收尾期间还通过界面手动验证了移动、开盾后守卫攻击扣除护盾、Q / R 输入与落地击飞，并确认不操作时会被击败。该手动轮次早于最终 LeapSlam 压身调整；最终模型的动作、命中数字与通关重新进行了上面的浏览器验收。

代码复核中修正了两个实际问题：守卫预警扇区的朝向原先反向；手动对齐的守卫攻击动画原先未推进淡入时钟。修正后用真实 Three.js AnimationMixer 执行当前动画函数，核对了攻击权重、显式采样时间和实际变换值；范围中心方向也与规则一致。

原生 Godot 执行 43 项 headless 自动检查，未执行可视窗口验收。移动端保留实机性能、触屏精确选点与长时间运行检查。截图和测试不能替代目标设备上的帧率、布料、贴图与操控手感验收。
